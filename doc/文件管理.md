# 文件管理(MinIO)

模板自带的文件能力:**字节存 MinIO,元数据存 `sys_file`**。上传走**预签名直传**(浏览器 ↔ MinIO),
应用服务器不碰字节流;所有应用侧接口仍然是 tRPC。

> 设计口径:**能砍就砍**。归属关系交给业务表(业务表存 `fileId`),不做 `biz_type/biz_id` 反向索引;
> 公开/私有由**桶**决定,不存 `visibility`;"谁传的"交给审计日志,不存 `uploader_*`。

---

## 一、表 `sys_file`(系统表第 15 张)

| 列 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | varchar(32) | PK | nanoid(`lib/ids.ts` 的 `newId()`);业务引用的就是它 |
| `bucket` | varchar(64) | not null | 桶名 —— **公开/私有由它决定** |
| `object_key` | varchar(512) | not null | `{yyyy}/{MM}/{nanoid}.{ext}` |
| `origin_name` | varchar(255) | not null | 原始文件名(下载时进 `Content-Disposition`) |
| `ext` | varchar(16) | | 小写后缀,不带点 |
| `content_type` | varchar(128) | | `confirm` 时以 MinIO 回的为准,**不信客户端** |
| `size` | bigint | not null default 0 | 字节,`confirm` 时 `statObject` 校准 |
| `hash` | char(64) | | sha256 —— **只当元数据/查重钩子,不自动去重**(真要做秒传才加 `ref_count`) |
| `status` | tinyint | not null default 0 | **0 待确认 / 1 正常 / 2 已删除** |
| `create_time` | datetime | | |
| `update_time` | datetime | | |

```sql
primary key (id)
unique key uk_sys_file_object (bucket, object_key)     -- 防重复登记
index      idx_sys_file_status (status, create_time)   -- 扫「待确认超时 / 已删除待清桶」
index      idx_sys_file_hash   (hash)                  -- 查重
```

⚠️ **建表要同步四处**(少一处老库就对不上,见 `doc/数据库与认证.md` 的「数据库」节):
`src/db/data-base-schema.ts`(drizzle,逐列 JSDoc)* `scripts/create-system-tables.ts` 的 `TABLES`(MySQL raw DDL)*
`scripts/create-better-auth-tables-dm.ts` 的 `STATEMENTS`(**达梦;本机 `.env.local` 就走达梦,这条是必须项**)*
`scripts/sync-table-meta.ts` 的 `TABLE_COMMENTS` / `COLUMN_COMMENTS`(注释唯一真源)。

验收:`pnpm db:create` 幂等;`pnpm db:sync:meta` **跑两次,第二次必须报「无需改动」**。

## 二、MinIO 侧约定

- **两个桶**:`app-public`(头像/图标,匿名只读,可直链、可被浏览器缓存)+ `app-private`(附件,私有,**只发预签名 URL**)
- **objectKey**:`{yyyy}/{MM}/{nanoid}.{ext}` —— **不用原文件名**(中文 / 特殊字符 / 重名全躲开);原名只在 DB
- **生命周期**:`app-private` 下 `tmp/` 前缀设 **1 天**过期 → 与 DB 扫 `status=0` **双保险**
- **预签名有效期**:PUT 10 分钟、GET 5 分钟
- **CORS**:实测**新版 MinIO 默认就会应答预检**(`OPTIONS` 回 `204` + 按 Origin 回显 `Allow-Origin` + `Allow-Methods: PUT`),
  所以浏览器直传**开箱可用**,不必先配。⚠️ 但如果你的版本 / 反代把预检挡了,症状是直传 403 或 `xhr.onerror`,
  这时才需要在控制台(`:9001`)或 `mc cors set` 里配:允许 `PUT`/`GET`/`HEAD`、允许 `Content-Type`、暴露 `ETag`。
  `minio` 的 JS 客户端**没有** `setBucketCors`,脚本设不了 —— 只能在控制台点或者用 `mc`。
- 初始化:`pnpm db:minio:init`(`scripts/init-minio.ts`,幂等:建桶 + 公开桶只读策略 + CORS)

## 三、两阶段上传流程

```
① 客户端  trpc.file.presign({ name, size, contentType, bucket })
          → 服务端算 objectKey、签发 PUT URL、落一行 status=0
          → 返回 { fileId, uploadUrl, headers, objectKey, expiresAt }
② 浏览器  PUT uploadUrl（字节直传 MinIO，不经过应用服务器；进度条天然可做）
③ 客户端  trpc.file.confirm({ fileId })
          → 服务端 statObject 校准真实 size / contentType、写 hash
          → status = 1；大小/类型不符 → 删对象 + 报错
④ 业务    保存时把 fileId 写进自己的业务列（如 sys_user.image）
⑤ 展示    trpc.file.url({ id }) → 公开桶拼直链 / 私有桶签 GET（5 分钟）
```

**为什么是两阶段**:预签名只保证"这个 key 可以写",不保证"真的写了、写的是什么"。
`status=0` 是**正常的中间态**,清理任务正好按 `(status, create_time)` 扫它。

**一次可以传多个** ✓:对话框里 `FileDropzone` 走 `multiple` + `onFiles`(它逐个校验、只把合规的交出来),
调用方维护一个**队列**(每行自己的进度 / 失败原因),再**顺序**上传 ——
并发传会把进度搅成一团,而且失败定位不了;单个失败**不中断其余**,行上直接重试即可。

### 秒传(hash 去重)

客户端在 `presign` **之前**算好文件内容的 sha256 一起提交;服务端按
**`(bucket, ext, hash)` + `status = 1`** 查一次,命中就**不再签发上传地址**,直接把那条已经存在的记录返回
(`instant: true`、`uploadUrl: null`)。浏览器因此**一个字节都不用传**。

三个条件缺一不可,各有硬理由:

| 条件 | 为什么 |
| --- | --- |
| 同 `bucket` | 对象在桶里;公开头像不能复用私有附件的对象 |
| 同 `ext` | 对象键里带着后缀;不同后缀共用会永远对不上 |
| `status = 1` | 待确认的对象可能压根没传上来;已删除的其对象可能已被清理 |

**为什么是「返回已存在的那一行」而不是新建一行**:表上有唯一索引 **`uk_sys_file_object(bucket, object_key)`**,
即「一个对象只能有一行」—— 硬插第二行会被数据库挡回来(实测 `[-6625] 违反唯一性约束`)。
这条约束反而让实现变简单:

- **不需要 `ref_count`**(不存在多条记录共用一个对象);
- **删除也不需要额外判断**(删掉唯一一行,对象就跟着清掉)。

⚠️ **两个诚实提醒**:

1. **客户端的 hash 是被信任的**:声称一个 hash 就能拿到那条记录的访问地址。彻底防住要在 `confirm` 阶段
   用真实字节重算 hash —— 但秒传路径**没有字节**,做不到;要更严就得给 `sys_file` 加**上传者列**并按人隔离去重。
2. **秒传不会替你改名**:命中时列表里不会多一行(文件本来就在),上传对话框那一行标「已存在」,
   鼠标悬停会告诉你复用的是哪个文件。

### 头像上传

- **一律进公开桶**:公开地址不过期、可直链、可被缓存 —— 头像最合适;上传成功后把**公开直链**写进
  `sys_user.image`(BA 的原生字段,零 schema 改动)。
- **显示的代价**:因此 `sys_user.image` 里存的是地址 ⇒ 换对外域名时**旧头像地址会失效**(新传的不会)。
  要彻底免疫就得改成存 `fileId` 再按需换地址,那要给 `sys_user` 加列、且每个渲染处都变成异步取地址 —— 复杂度明显更高,
  当前不做。
- 列表 / 详情统一用 `ui/avatar`(`Avatar` + `AvatarImage` + `AvatarFallback`)渲染:没有地址或图挂了都会退化成**姓名首字**,
  所以种子数据里那些 `https://picsum.photos/...` 外链也能正常显示。

**没有 `api/upload` 路由** —— 上传接口仍是 tRPC 的**小 JSON**(只签 URL),字节流走的是外部对象存储,
所以 AGENTS「接口铁规」不需要为此开口子。

## 四、接口(`src/integrations/trpc/routers/file.ts`)

| procedure | 说明 | 权限 |
| --- | --- | --- |
| `file.presign` | 校验白名单/大小 → **hash 命中已有文件则秒传**;否则签 PUT + 落 status=0 | `sys:file:upload` |
| `file.confirm` | `statObject` 校准 + 写 hash + status=1 | `sys:file:upload` |
| `file.url` | 公开桶直链 / 私有桶预签名 GET | 登录即可 |
| `file.list` | 台账分页查询 | `sys:file:list` |
| `file.remove` | 删 MinIO 对象 + status=2 | `sys:file:remove` |

---

## 五、安全

- **白名单**:后缀 + contentType 双校验,默认 `image/*` + `pdf/xlsx/docx`;参数化可配
  (`file.allow_ext` / `file.allow_content_type` / `file.max_size_mb`,进 `PARA_DEFAULTS`)
- **大小上限**:`file.max_size_mb`,presign 与 confirm **两头都校验**(客户端能绕过 presign 的 size 字段)
- **私有桶绝不返回永久 URL**,预签名有效期 5 分钟
- 删除必须过权限点;**上传受后缀白名单 + 大小上限双约束**(presign 与 confirm 两头都查)
- **拦存储型 XSS**:公开桶是直链、浏览器按 `Content-Type` 渲染 → `confirm` 明确拒绝 `text/html` / `image/svg+xml` / `application/xhtml+xml`

## 六之一、已知缺口

- **没有服务端登录校验**:`file.*` 与另外 7 个路由同口径(界面靠 `(main)` 守卫 + `useHasPerm`)。
  加硬校验会让 `presign/confirm/remove` 无法集成测试 —— `getCurrentUserId()` 在直调 caller 里恒为 null。
  正解:`init.ts` 加 `protectedProcedure` + 测试能注入会话,与审计日志中间件一起做。
- **没有归属列**:`biz_type`/`biz_id`/`uploader_*` 是刻意砍掉的(精简);代价是"这条数据挂了哪些附件"要业务表自己看,
  "谁传的"靠审计日志。

## 七、清理(并入定时任务那批)

1. `select … where status = 0 and create_time < now() - interval` → 删 MinIO 对象 → `status = 2`
2. `status = 2` 的残留对象再删一次(兜底)
3. MinIO 生命周期(`tmp/` 1 天)做**双保险** —— 应用挂了也不会一直堆垃圾

## 八、排障

| 症状 | 原因 |
| --- | --- |
| 浏览器直传 403 / CORS 报错 | 桶没配 CORS,或预签名过期(10 分钟) |
| `confirm` 报大小不符 | 预签名时客户端报的 size 是假的 → 以 `statObject` 为准 |
| 私有桶 `<img src>` 不显示 | 私有桶不能用直链,必须走 `file.url` 现签 |
| 换了对外域名后 URL 全废 | 别存 URL,只存 `bucket` + `objectKey`;`MINIO_PUBLIC_URL` 只影响拼出来的直链 |
| 达梦上建表失败 | 忘了同步 `create-better-auth-tables-dm.ts` 的 `STATEMENTS` |
| 运行时 `Cannot find module '#/lib/storage'` | **同名文件 + 同名目录**(`storage.ts` 与 `storage/`):`tsc` 选文件、Nitro 当目录 ⇒ 实现文件必须扁平命名(`storage-minio.ts`)|
