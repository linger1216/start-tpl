# 数据权限（行级可见范围）

功能权限决定能否调用接口；数据权限决定调用后能看到哪些行。页面、按钮和接口授权见 [RBAC 权限模型](rbac-权限模型.md)。

## 模型

- `sys_data_policy` 保存主体、资源表、判据列、插件标识、值域 key 和状态。
- `sys_data_plugin` 保存用户配置的指定清单 `output_values: [{key, value}]`。它是数据，不是可执行代码；函数型插件只在代码中内置。
- 主体为 `*`、`user:<id>`、`role:<id>` 或 `dept:<id>`；部门主体匹配本人直接所属部门。
- 规则有两种形态：判据列和插件都为空时为「整类可见」；二者都有时将插件结果编译为 `列 IN (值...)`。表名和列名须通过标识符校验，值使用参数绑定。
- 插件返回字符串字段的对象数组；按规则的 `value_key` 取字段。旧规则未设置 `value_key` 时按列名取，缺失时回退到 `value`。空字段和重复行会被清理；标量或数字不会隐式转换成权限值。旧数据库清单里的字符串数组仍由 `parseItems` 兼容。

## 范围计算

同一资源的已上线规则按 **OR 并集**计算。下表适用于普通登录用户；管理员和外链访客的例外见下。

| 情况 | 结果 |
| --- | --- |
| 资源没有上线规则 | 不增加行过滤条件 |
| 有上线规则，但没有任何主体命中 | `1 = 0`，不返回行 |
| 命中「整类可见」 | 不增加行过滤条件 |
| 插件返回空集 | 该规则不返回行 |
| 上线规则主体无效、填了列却没有插件，或插件不存在、停用、抛错、取不到所选 key | 该规则跳过并记录日志；若没有其他有效规则，则不返回行 |
| 多条有效规则命中 | 取各规则允许范围的并集 |
| 没有用户上下文 | 抛错 |

**安全边界：**没有上线规则是未启用过滤，不是拒绝访问；应在上线业务前配置并预览规则。管理员和外链访客在 `dataScopeMiddleware` 中绕过行级过滤；访客能访问的页面由分享令牌限制，但该页面若读取数据，行级规则不会再缩小范围。分享前应确认页面数据适合完整公开给令牌持有人，详见 [外链分享](外链分享.md)。

## 内置值域

| 标识 | 结果 |
| --- | --- |
| `self` | 当前用户 id |
| `my_departments` | 所属部门及下级，返回 id 和名称 |
| `my_dept_ancestors` | 所属部门及祖先 |
| `my_dept_only` | 仅直属部门 |
| `my_sub_departments` | 所属部门的下级，不含本级 |
| `my_street` | 祖先链中匹配内置闵行街镇名称的第一个节点 |
| `my_neighborhood` | 祖先链中名称包含居委会或村委会等关键词的节点 |
| `my_street_tree` | 匹配街镇及其下级 |

内置项不能通过管理界面修改或删除，也不能被同名清单覆盖。`fixed` 是隐藏的保留 key，返回空集，防止同名占用；未知插件不会回退到它。`my_street` 和 `my_street_tree` 依赖代码里的闵行街镇名单，`my_neighborhood` 依赖名称关键词；这些是示例地域约定，派生时须先核对现有规则引用和组织命名，不能直接删除或替换后假定可见范围不变。

## 配置与预览

`/settings/data-plugins` 管理清单插件；`/settings/data-scope` 管理规则。插件与规则的写操作分别受 `sys:plugin:*` 和 `sys:scope:*` 权限点控制。

| `status` | 界面 | 是否参与过滤 |
| --- | --- | --- |
| `2` | 启用 | 否，可预览并上线 |
| `1` | 上线 | 是 |
| `0` | 停用 | 否 |

新增规则默认处于 `2`，接口也接受显式状态。修改已上线规则的主体、资源、列、值域 key 或插件且未显式指定状态时，会退回 `2`；只改备注不会。修改插件清单不会自动改变引用规则的状态，因此修改前后应预览受影响规则。

规则行内预览调用 `dataScope.trial`，按当前用户或接口指定用户计算基线与试算结果，展示规则命中情况、可见行数及样张。预览有读取业务数据的能力，应只授权可信管理员。插件预览 `dataPlugin.test` 使用当前登录用户，返回上下文和原始输出行。

## 为读接口接入

1. 在 `src/lib/rbac.ts` 的 `DATA_SCOPE_BY_PATH` 中登记接口与资源；不受数据权限约束的 query 必须登记到 `UNSCOPED_QUERIES` 并写明理由。
2. 在 resolver 取得 `const scope = await ctx.scope()`，将其并入查询的 `where`。`undefined` 表示无过滤条件，是合法结果；不要自行把插件异常当作全部可见。
3. 在隔离测试库验证无规则、未命中、空值、插件不可用、多规则并集和管理员旁路。`tests/auth.test.ts` 检查 query 分类，`tests/data-scope-core.test.ts` 用独立虚拟资源名和测试部门行验证核心 SQL 过滤；`tests/data-scope.test.ts` 进一步覆盖 demo 表的预览、CRUD 和接口路径。

守卫不会自动改写 SQL：**登记资源后仍须在每个受约束的查询里调用 `ctx.scope()`**。`ctx.scope("表名")` 可明确指定资源；无登记且不传资源会报错。

## 代码与缓存

- `src/lib/data-scope-spec.ts`：浏览器和服务端共享的主体、状态和清单校验。
- `src/lib/data-scope-plugins.ts`：内置值域、清单装载和求值。
- `src/lib/data-scope.ts`：上下文装配、规则编译和预览。
- `src/lib/data-scope-meta.ts`：资源和字段元数据。
- `src/integrations/trpc/routers/data-scope.ts`、`data-plugin.ts`：规则及插件接口。

规则、插件、部门树和资源元数据各有 30 秒进程内缓存；规则、插件或部门写入后分别调用 `clearDataScopeCache()`、`clearPluginCache()`、`clearDeptCache()`。多实例间不共享失效通知，其他实例可能在 TTL 内读取旧值；插件求值超时为 3 秒。元数据依赖 MySQL `information_schema`，读取失败时降级为空清单；达梦及元数据限制见 [达梦支持](达梦支持.md)。

## 升级与排查

- 表和字段注释由 `scripts/sync-table-meta.ts` 对齐；系统表结构和双库维护边界见 [数据库与认证](数据库与认证.md)。
- 历史版本曾把规则 `params` 和插件函数体迁为插件 `output_values`；当前建表脚本包含旧列删除。**旧库升级前先备份并检查这些列的数据及依赖，制定迁移方案后再运行 DDL**，不要假设旧函数或规则参数会自动转换成清单。
- 已有上线规则若主体格式损坏，或填了判据列却没有插件，现在不会再被误判成“资源无规则”而放行；上线前应核对 `sys_data_policy` 的历史脏数据，修正后再部署。
- 手写 MySQL SQL 时注意 `column` 是保留字；多条规则测试必须清理自身规则，避免 OR 并集使结果误判。
- 具体行为以 `src/lib/data-scope*.ts` 和集成测试为准，历史变更可查 Git。
