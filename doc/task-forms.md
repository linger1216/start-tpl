# 任务填报设计

> 链接块就地作答及把答案存入 `tc_task.draft/answer` 的旧方案已废止。独立填报、批次、汇总与受限 Excel 均已落地，界面接入任务详情、设计器与批次页。

## 边界

任务说明里的链接块只供阅读；自由回复 `TaskComment` 保存文字、附件及 @。可选的 `TaskReport` 独立保存结构化填报，不把评论或任务 payload 当作正式提交。

一个任务最多一个有效执行人，执行权随转交改变，填报数据仍属于任务。流程模板在创建任务时复制快照；填报模板发布后版本不可变，每份任务填报绑定确定的版本。填报实时保存，不自动完成任务，完成条件由流程动作和守卫决定。

## 目标模型

| 业务对象 | 计划存储 | 职责 |
| --- | --- | --- |
| `TaskReportTemplate` | `tc_report_template` | 模板名称和管理信息 |
| `TaskReportTemplateVersion` | `tc_report_template_version` | 不可变的发布结构 |
| `TaskReport` | `tc_task_report` | 任务填报与 revision(父子共享根任务那一行) |
| `TaskReportSubmission` | `tc_report_submission` | 历史快照(旧提交模型的遗留,当前流程不再写入) |
| `TaskReportBatch` | `tc_report_batch` | 征集活动、版本、截止时间和汇总规则 |
| `TaskReportBatchTask` | `tc_report_batch_task` | 批次与独立任务的关联；一个任务最多属于一个批次 |

批次不是父任务，不影响各任务状态。批次创建在单一事务中完成，按创建人和请求键幂等；失败时整体回滚，可使用同一请求键重试。关闭批次或超过截止时间后不接受新的正式提交，已提交的任务和历史保留。汇总按当前有效提交确定性计算，不持久化重复的汇总真源；支持追加行、按业务键合并并提示冲突、指定数值字段的求和、计数和平均，保留提交人、任务及行来源。

新建任务和任务详情均可创建填报模板或为本人模板发布新版本；已有任务仍绑定原版本。编辑器保留未在界面中修改的高级字段配置。新建任务可以同时选择填报模板，任务与填报行在同一事务中创建。创建人与当前执行人均可填写并导入，以 revision 检测并发修改；模板在创建任务时固定，**不能更换或移除**。任务详情可直接从已保存的表格填报发起分发，也可在批次中选取创建人自己的源任务表格草稿，可为每位执行人选择不同字段及等于的值（多选字段除外）；每行必须恰好分配一次，且每人至少一行。界面和服务端都会检测未分配及重复命中的行。服务端在事务内校验源草稿版本，若数据已变更则要求重新检查，再读取并拆分，分别保存到独立任务，源任务保持不变；幂等重试返回原批次。源任务可按名称搜索；每次最多显示 100 条匹配结果。分发时的源任务、草稿版本、字段、筛选值和初始行数作为任务事件在事务内保存；批次详情显示初始条件（转交不改变原条件），无分发来源的旧批次不显示。条件详情仅任务相关方、创建人、管理员及批次管理者可读取。

模板管理可删除由本人创建的模板（管理员也可删除）；删除需要 `sys:tc_report_template:remove` 按钮权限。删除只移除模板入口，保留不可变版本以供已有任务和批次读取，不能再将这些版本绑定到新任务或新批次。删除和新绑定通过模板行锁串行。旧环境可执行 `pnpm db:add:task-report-permission` 单独补充此权限点，再在角色管理中按需授权；此命令不会创建用户或角色，也不会修改现有授权。若权限点已删除或与现有菜单冲突，命令会退出并要求人工检查。

**批次三处接口的可见口径一致**：`reportBatchList` / `reportBatchGet` / `getBatchSummary` 都放行「创建人本人 **或** 管理员」。列表若只按 `creator_id = me` 筛，管理员能按 id 打开任意批次却在列表里找不到入口，是同一份权限判据的三处漂移。

**批次详情与汇总对软删任务的口径不同，且是有意为之**：`reportBatchGet` 返回的 `tasks` **不筛** `alive`，已软删的任务仍以 `deletedAt` 标出并保留在列表里，方便追溯「这批当时发给了谁、谁的任务后来被删了」；统计「已提交 X/Y」时也只按未删任务计入分子（见界面 `task-report-batches.tsx`）。而 `getBatchSummary` **筛** `alive`，因为汇总是对现存有效提交做运算。**不要「顺手」给 `reportBatchGet` 补 `alive` 过滤器** —— 那会让已删任务从进度视图里消失，与历史记录口径不符。

## 数据与交互

模板以稳定 schema 标识定义一个或多个 OBJECT / TABLE 数据集，服务端负责字段类型、默认值、必填、条件和跨字段校验。**没有草稿 / 提交 / 退回这组状态**:填报实时落库(前端 600ms 防抖,每个任务一行、自己的 `revision` 乐观锁),模板在创建任务时固定、不能更换或移除。**下发即复制**:fan-out 时子任务拿到父任务母版行按自己数据范围切出来的独立副本,之后父子各改各的,同一行被多人修改也不会互相加锁或报冲突。子任务详情里的**「保存」**按钮才把这份副本同步回父任务:父行 = 父行里不属于我范围的行 ∪ 我的行,再用父数据按我的范围回灌我的视图 —— 所以改掉范围字段的行保存后从我的视图消失、在父任务里归到别人的范围。多个执行人的数据范围不允许完全相同(建任务时拦),删父任务会连带软删子任务。模板与填报操作均需任务级授权,并在事务内记录关键业务日志(同步记 `report.sync`)。

二维表格提供增删行、上下方向键在行间移动、从电子表格整块粘贴（按起始格铺开，超出表格范围丢弃）、错误定位到行与字段，以及受限 Excel 导入导出。导入只接受平台模板并限制文件大小、工作表和行列数量；导出时防范公式注入。附件如纳入填报，复用既有文件鉴权链路。

Excel 使用 [SheetJS 官方发布的 0.20.3](https://docs.sheetjs.com/docs/getting-started/installation/frameworks/)，不再使用 npm 上的 0.18.5；后者受 [GHSA-4r6h-8v6p-xvw6](https://github.com/advisories/GHSA-4r6h-8v6p-xvw6) 影响。导入前使用 yauzl 逐条读取压缩包并累计实际解压字节，上限为 5 MB 文件、20 MB 解压数据、150 个条目、一个工作表、100 列和 10000 行；拒绝宏、外链、公式、嵌入对象和 XML 外部实体。导入直接解析:成功就落值并报「成功 N 条」,有失败行则整批不落值并报「成功 X 条 · 失败 Y 条」+ 原因(不自动提交)。**表头只有一行中文列名**(字段英文 id 是内部标识,不写进文件),按中文名匹配;老格式(首行英文 id + 第二行中文名)仍能读。批次汇总可导出全部当前结果及冲突与来源。

## 实施顺序

先收紧单执行人、任务动作守卫及串并行流程；再实现模板版本与实时保存填报；随后实现批次、来源可追溯汇总与 Excel；最后接入任务详情、设计器和批次界面，并验证并发、权限和数据库方言。
