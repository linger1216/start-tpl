# 任务填报

任务可绑定一个填报模板；自由评论和附件不作为填报。模板为单版本，编辑会影响已绑定任务读取的结构，删除只隐藏入口，已有任务仍可读取。

每个任务的 `tc_task_report` 保存自己的草稿和 revision。创建人与当前执行人可编辑；保存以 revision 检查并发。多执行人下发时，父任务保存母版，子任务取得按筛选条件切出的独立副本。子任务手动同步时，按范围替换父任务对应行，并用结果刷新自己的副本。筛选范围在创建时必须两两互斥。同步不检查父任务自下发以来的修改，可能覆盖父任务同一范围的编辑；历史任务的筛选条件也可能重叠。

当前没有提交、退回、批次或汇总流程（早期设计里的 `tc_report_batch` 没有落地,库里不存在）；不要据此新增第二套状态。
`tc_report_submission` 现在只有一个用途:**表单填报同步给父任务时的那份不可变快照**(见下),不做审批流转。

**父任务看到什么**:父任务的数据全部来自子任务的同步,没有别的来源,也不做实时兜底 ——

- 表格填报:子任务点「保存」= 用自己的行整片替换父任务中属于自己范围的行,父任务读的就是这份母版行;
- 表单填报:表单只有一个对象、没法按行合并,所以每次点「保存」往 `tc_report_submission` **追加一份快照**,
  并把 `tc_task_report.current_submission_id` 指过去;父任务只读这些**已保存**的快照。
  子任务只是自动存草稿(没点保存)时,父任务**什么都看不到**;同步之后又改草稿,也要**再点一次保存**父任务才会更新。

父任务看子任务填报时**按字段类型渲染,不显示原始 JSON**:单选 / 多选给取值、数组按「第 N 项」展开元素字段、
附件是可以点开的**附件名**(原名)。附件地址一律现签(`taskClose.attachmentUrl`),放行范围与 `reportGet` 的可见集合一致 ——
自己那份草稿 + 子任务**已保存快照**里的附件(数组元素里的附件也算,见 `reportAttachmentIds`);没保存的签不出来。

**字段类型**:文本 / 手机号码 / 邮箱 / 整数 / 小数 / 日期 / 日期时间 / 单选 / 多选 / 文件附件 / 数组。
**日期 / 日期时间的口径**(与全站一致,见 `lib/time.ts`):**存**统一格式 —— 日期 `YYYY-MM-DD`、日期时间带时区的 ISO;
**给人看**一律折成本地 `YYYY-MM-DD HH:mm:ss`(`datetime-local` 输入框用本地 `YYYY-MM-DDTHH:mm`),
界面、只读的「子任务填报」、导出的可读表都走这一条,不把 UTC 甩给人。**导入**时人也只需要写本地写法
(`2026-11-14 10:23`、`2026/11/14`),或直接用 Excel 的日期单元格(读出来是序列号,我们会折算);
认不出的值**保留原文**交给校验报错,不会悄悄当空值丢掉。
模板里的字段顺序就是填报顺序,左侧把手可以**拖拽调整**(HTML5 拖放,与字典项 / 列设置面板同款交互)。
手机号按中国大陆规则(`^1[3-9]\d{9}$`)校验,邮箱走 `z.email()`,附件存 `sys_file.id` 列表(选完即传、最多 20 个、
展示用 `reportGet.files` 解出文件名,**点文件名直接预览**(下载时按原名存盘)。**数组**元素的字段在模板里单独配置(至少 1 个,元素层不再允许数组)——
填报表单里该字段带「添加」按钮,点一次加一条空对象再逐项填写;提交时逐项校验必填与类型,一次只报第一条
(`第 N 项「字段」…`)。Excel 导出把数组写成 JSON,导入按 JSON 解析回对象数组;粘贴(TSV)跳过附件与数组字段。

表格支持编辑、粘贴以及受限 Excel 导入导出。导入限制文件大小、解压量、工作表和行列数量，并拒绝公式、宏及外链；表头使用中文字段名。任务与权限、事务和通知见 [任务闭环](task-close.md)。

**导出「父子所有填报数据」**：父任务导出时，除自己那份之外还要带上子任务的填报 ——

- 表格填报：父任务那张母版本身就并进了子任务同步过来的行，所以「填报」一张表就是全量；
- 表单填报：一个对象装不下多个子任务的值，于是另起一张 **「子任务填报」** 工作表，**每个已保存的子任务一行**（首列「执行人」，其后是各字段）。

数据源与界面同一份口径：只算子任务**点过「保存」**的快照，没保存的不进导出（不做实时兜底）。

**一份文件最多四张表**（`createReportWorkbook`，都不隐藏；表名与张数见下表）：

| 任务形态 | 工作表（自上而下） |
| --- | --- |
| 父任务（有子任务，且至少一个子任务保存过） | `父任务填报(可读)` · `父任务填报` · `子任务填报(可读)` · `子任务填报` |
| 父任务（子任务都还没保存） | `父任务填报(可读)` · `父任务填报` |
| 普通任务（没有子任务） | `填报(可读)` · `填报` |
| 「下载模版」（空表，用来填完导入） | `填报` |

| 表的口径 | 内容 | 用途 |
| --- | --- | --- |
| `…(可读)` | 附件写**原始文件名**、数组写「1) 姓名:张三，年龄:22；2) …」、多选顿号分隔；数字仍是数字 | 直接发给别人看 / 打印 |
| 不带后缀的 | 机器格式：附件是 `sys_file.id`、数组是 JSON | **导入只认这一张**，`导出 → 改 → 导回` 靠它 |

「子任务填报」两张都以**执行人**为首列；表单一个子任务一行，表格一个子任务按它自己那份铺开成多行。

导入按**表名**认表：依次找「填报」「父任务填报」；只有一张表时（手搓的文件、下载的模版）就直接用它；
多张表却没有这一张 → 明确报错，不瞎猜一张。「子任务填报」天然不属于某一个任务，**不参与导入**。
