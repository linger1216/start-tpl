# 面向收敛的重构方案

## 目标和边界

模板的最小闭环是：初始化数据库和管理员 → 登录 → 页面及接口授权 → 管理用户、角色、部门与菜单 → 审计和基础配置 → 派生新项目。文件、通知、数据权限、双库和任务示例已有真实调用与产品承诺，应先证明可以独立移除或替换，再调整默认范围。组件库和工作台中的组件示例保留；仅在接口和行为高度重合、调用迁移完成时合并组件。不要以压缩行数为目标，也不要为消除一个抽象而复制复杂逻辑。

以下区分已执行修改和后续方案；候选项不是已完成的改动。各阶段应独立验证；任何涉及现有数据、权限或对外行为的变化先写迁移与回滚，再执行。不要运行破坏性数据库清理来验证方案。

## 现状和主要问题

1. **产品范围需要持续保持一致。** README 的样本模块及视觉规范描述已与 `PRODUCT.md`、`DESIGN.md` 对齐；派生后的文档仍需随所选功能核对，不凭旧叙事删除业务。
2. **派生工具与源码文本强耦合。** `features.json` 和 `scripts/prune-features.mjs` 的规则依赖具体 import、注释、行文本和正则，功能变更时需要同步多处。裁掉 demo 后的测试提示已修正；未使用且混入可选表的 `core.tables` 已删除。
3. **模板中残留具体组织的规则。** `src/lib/data-scope-plugins.ts` 写死闵行街镇和居村名称判断；这些规则被数据权限策略及测试引用，删除前必须检查现有 `sys_data_policy.plugin_key`，否则可能改变可见范围。通用模板不应默认假定特定行政区。
4. **存储实现需保持打包边界。** 唯一的 MinIO 实现与客户端可引用的纯函数仍分文件，服务端动态加载有真实的打包隔离作用；已删除只为单一实现重复声明的接口及参数。
5. **文档与兼容历史混在现行规则里。** 数据权限插件文件中保留大量版本历史与旧形态兼容说明；历史返回值归一化接受字符串、数字、对象，而当前运行的插件只返回对象数组；持久化旧清单的兼容与运行时返回值兼容需要分别处理。
6. **权限空表有特殊语义。** `src/components/layout/nav-data.ts` 区分 `rows=[]`（使用静态菜单）与 `rows=null`（无权限），服务端对菜单表为空也有放行语义。这是跨前后端的状态分支，不是简单 UI 兜底；更改前必须单独设计初始化和迁移，防止误授权或锁死管理员。
7. **多处事实需要人工同步。** 系统表结构涉及 Drizzle schema、MySQL / 达梦 DDL、元数据脚本；已有数据库可能与建表脚本漂移。权限映射、路由、种子和裁剪规则也需同步，修改必须覆盖完整链路。

## 已执行：文件访问规则收敛

`src/lib/storage.ts` 的 `getObjectUrl` 统一公开预览直链、私有访问及下载预签名；`file.url` 与任务附件访问分别保留原有记录检查、权限和返回字段。缩略图的短时效签名维持原路径。下载仍使用原文件名。公开直链拼接只保留 `publicUrlOf` 一处，上传签名不再接收未使用的 Content-Type 参数。该步骤没有改变数据结构或接口路径。

存储入口直接从唯一的 MinIO 工厂推导类型，签名默认时效由实现持有；去掉重复的接口声明及只在一个调用点传递的选项，同时保留动态加载和原有时效。

存储区分对象不存在与桶不存在：前者仍幂等，后者抛错，防止文件删除时把配置故障当成成功并修改记录状态。测试连接真实 MinIO，覆盖两类错误和删除接口的状态保持。

上线规则的主体无效或缺少插件时不再被加载阶段丢弃成“无规则放行”；损坏规则被记录并跳过，若没有其他有效规则则返回空集。部署前应检查并修正历史脏规则。

数据权限求值已移除旧插件返回标量与数字的隐式转换，保留空字段清理、去重、旧数据库清单解析和缺失插件处理。现有代码无用户函数加载路径；若派生项目自行修改过内置插件并返回标量或数字，需先改成字符串字段对象数组。

“我的部门及以下”插件现在只读取一次组织树快照，再用于遍历与名称映射；保留现有归属节点判定，避免直接使用可能包含失效部门 ID 的上下文列表。

权限测试不再在菜单、权限点或管理员角色缺失时静默返回；前置条件不满足会失败并提示在隔离测试库初始化。之前“菜单表为空”的警告无条件打印，不能据此判断数据库状态。

裁剪任务闭环时同步移除外壳红点预取；通知授权断言归入通知测试。派生组合测试在临时目录运行真实裁剪、路由生成和类型检查。

裁剪任务闭环时同时清理红点查询的数据范围分类，避免保留悬空接口。最小功能加测试的派生产物已运行完整测试：203 项通过、2 项跳过（派生工具已移除）；自动回归还会在该组合运行权限分类守卫。

不选工作台时保留基础首页，避免登录默认回到 `/` 后出现 404；同时修复多个未选模块共同涉及的文件在复制时已排除、后续裁剪规则仍报缺失的问题。仅跳过明确属于未选模块路径的缺失文件，其余规则失配仍报错。测试覆盖最小派生的复制路径，以及裁剪后路由生成和类型检查。现有裁剪仍依赖源码文本匹配，模块边界的进一步调整保留在 P3。

功能选择先应用显式取消、再补齐保留模块的依赖，不再因取消参数的顺序产生不同结果；未知的取消项也会报错。仍被保留模块依赖的选项会保留并提示。

日志覆盖测试直接遍历非空的实际接口树并验证每个接口的日志，删除清单中重复的接口计数、测试中的手写总数，以及派生时改写测试文件的逻辑；新增接口仍会自动进入行为验证。

规则组合、主体与 SQL 标识符的纯规格测试已从 demo 表集成测试拆出，裁掉 demo 但保留测试套件时仍可执行；新增不依赖 demo 表的核心 SQL 集成测试，覆盖无规则、主体匹配、并集和失效插件；demo 表上的预览、CRUD 与接口链测试仍需迁移独立夹具。依赖 demo 接口的管理员旁路测试已归入 demo 集成测试，避免裁剪后 `auth.test.ts` 引用不存在的接口。

已删除仅供画廊展示、没有业务调用的时间式编号格式化与固定前缀；内部主键仍使用 nanoid。画廊不再在渲染期间生成随机 ID，避免服务端和客户端展示不一致。

删除 Excel 中未接线的旧三行解析器、文件校验及第二字段行扩展；现有导入对话框、导出和模板写盘保留，并增加真实写盘回读测试。原 `writeSheet` 的 `fieldRowValues` 和 `withDate` 参数已移除；如派生项目调用过，需自行迁移。

tRPC 客户端统一为默认的 `httpBatchLink`，移除 `VITE_TRPC_STREAM`；先前显式启用该变量的派生项目若需要批流响应，需自行接回流式 link。通知 SSE 不受影响。

已删除只供画廊展示的 Zustand 假后端及其依赖；表格行类型改名为 `TableRowData`，避免真实表格继承 mock 概念。UI 组件和台账表格示例保留。

数据权限文档改为当前契约、范围语义和旧库升级风险，删除与代码冲突的历次设计记录。工作台移除与框架 demo 重复的全局状态示例；UI 组件保留。

日期范围选择器已复用现有 Popover 和本地日期格式化，去掉手写浮层定位及事件监听；保留区间日历和快捷范围。

抽屉改用 Base UI 的进入、退出过渡属性，修复打开后面板与遮罩始终透明的问题；位移改为等值的常用 Tailwind 类。已在浏览器验证显示、Escape 关闭和焦点返回。

README 已移除过期的历轮改造记录，保留当前测试覆盖率口径并修正派生初始化与数据库隔离说明；样本模块和设计规范描述也已对齐；`Alert`、`MetaRow` 和提示箭头换用等值常用 Tailwind 类，组件与交互保留。

派生项目裁掉 demo 时，同步移除仅供演示使用的三个 TanStack 表单与状态依赖；保留 demo 的项目仍保留这些依赖。初始化安装允许更新派生产物的锁文件，以适应裁剪后的依赖清单。

## 分阶段实施

### P0：锁定基线与产品边界

- 建立可复现的空库启动、登录、授权、系统设置、文件上传及任务示例冒烟路径；记录 MySQL 和达梦各自可用的环境，不能将一侧通过当作双库通过。
- 将 README 的产品范围、设计描述、启动步骤与当前 `PRODUCT.md`、`DESIGN.md` 和代码逐项核对。README 写当前入口与操作，具体设计及历史放各自专题；避免重复维护精确组件数和过期表数。
- 保留所有 UI 原语及画廊；逐项盘点真实调用、可访问性、受控状态与键盘操作，不因画廊是唯一调用方而删除。对任意值类逐项判断：等价且不影响布局时换常见 Tailwind 类；与设计尺寸或响应式约束有关的保留并说明，避免机械替换。

验收：文档入口与实际代码一致；空库初始化及基本权限可重复；检查和测试基线记录具体失败，不隐藏已有问题。

### P1：从运行链中收敛重复和状态

- 文件模块：已统一两个地址分支；补覆盖公开预览、私有预览、公开下载和任务附件归属拒绝的集成验证。已移除 `Storage.publicUrl` 的重复拼接，同时保留客户端打包隔离与缩略图逻辑。
- 数据权限：梳理插件加载、归一化、失败与空集的区别；给实际调用的内置插件和清单插件建立契约测试，确认不存在旧插件后，再删仅为假设旧调用保留的转换及历史注释。**异常、缺失插件和空结果的授权语义必须逐例测试**，不得把失败改成放行。
- 静态菜单：先明确「未初始化」「用户无权限」「数据库不可用」的三种状态及管理员恢复流程。仅当种子和升级脚本能保证菜单存在时，才考虑移除空表放行和静态运行时回退；页面守卫、接口守卫、SSR 与菜单展示必须同一变更中迁移。
- 清点 UI 中职责重叠的组件，按真实 props 和调用场景比较；只有替换后不丢受控行为、可访问性、键盘及滚动约束才合并。统一组件的 Tailwind 类只做等价替换并在浏览器检查窄屏和弹窗滚动。

验收：现有接口与权限结果保持一致；测试覆盖失败关闭、SSR、下载与组件交互；无新增 lint 警告。

### P2：隔离可选样本与具体地域

- 把任务闭环和 demo 明确定位为样本；先盘点路由、菜单种子、tRPC、权限、通知、DDL、元数据、测试和文档的引用图。保留当前默认能力，优先把样本依赖从核心中拆出，而不是直接删表或改用户数据。
- 将具体地域值域改为显式样本配置或派生项目实现。迁移前查询现有策略引用并导出映射；为旧 key 提供明确迁移和不可迁移项报告，校验迁移前后可见集合；无法映射时拒绝升级，不静默扩大可见范围。
- 为每个选配组合维护清晰依赖：任务依赖通知；涉及数据权限的 demo 夹具必须由独立测试夹具替代，不能随 demo 删除核心权限测试。

验收：默认模板和裁剪后的最小模板都可构建、登录、授权并运行核心测试；旧策略迁移前后数据可见范围一致。绝不自动删除旧库业务表。

### P3：重做派生与数据库一致性检查

- 先为现有 `new-project.sh` / 裁剪器建立临时目录端到端测试，覆盖默认、最小和依赖组合；检查生成项目的安装、路由生成、类型检查、构建、权限分类与测试覆盖。
- 评估将可选样本移动为独立目录/模块并通过显式入口组合，或提供固定的精简模板分支；以实际维护与构建成本选择一种。替换前保留现有裁剪器，逐条迁移并对比产物；不要再新增依赖注释的文本切割规则。
- 明确 schema、两套建表及元数据的责任边界，增加只读差异检查（表、列类型、索引、约束）并输出可执行迁移建议；不把 `CREATE TABLE IF NOT EXISTS` 当作升级机制，不自动修改生产数据库。

验收：选配组合不依赖注释位置；核心安全测试不被裁掉；旧库差异可见，迁移脚本可重复执行并有回滚说明。

## 验证与交付顺序

每阶段先做调用链盘点与针对性测试，再跑 `pnpm typecheck`、`pnpm check`、`pnpm build`、`pnpm test`；改路由后额外跑 `pnpm generate-routes`。`pnpm check` 会写文件，检查其 diff；集成测试依赖 `.env.local` 指向的数据库及 MinIO，应使用隔离测试环境并记录不可用项。权限、数据迁移和 UI 行为分别做负例验证；每阶段保留可回退的提交及迁移前备份。全部阶段完成后重新测量文件数、依赖数、初始化步骤与派生组合，避免以行数下降替代正确性。
