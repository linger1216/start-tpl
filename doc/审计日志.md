# 鉴权与审计(服务端)

这篇讲一起落地的三件事:**谁能调接口**(登录 + 权限)、**谁调了什么**(审计台账),
以及**这一路上发生了什么**(stdout 日志,见 §七 —— 排查问题先看它)。前两件共用
`src/integrations/trpc/init.ts` 的中间件链,所以放在一起看。

## 一、中间件链(顺序是有意的)

```
publicProcedure    = t.procedure.use(logging).use(audit)
protectedProcedure = t.procedure.use(logging).use(requireUser).use(audit).use(perm)
```

| 节 | 做什么 | 为什么在这个位置 |
| --- | --- | --- |
| `loggingMiddleware` | stdout 日志 + `traceId` + 入参脱敏 | 最外层:任何调用都有日志 |
| `requireUser` | 解析并注入 `ctx.user`;拿不到 ⇒ `UNAUTHORIZED` | 在 audit **之前**:审计只记**已认证**的动作,未登录的尝试留在 stdout |
| `auditMiddleware` | 把每次**写调用**记进 `sys_log` | 在 perm **之前**:所以"已登录但没权限"的**拒绝也会留痕**(status=0 + `FORBIDDEN`)|
| `permMiddleware` | 按 `path` 查 `PERM_BY_PATH`,登记了就校验 | 最内层:权限不足不该进 resolver |

**14 个 router 共 105 个 procedure 全部走 `protectedProcedure`**(39 query / 66 mutation)——
未登录**一个都调不动**。HTTP 层实测:不带 cookie 打 `file.remove` ⇒ `401 请先登录`。

## 二、测试为什么要"注入用户"

直调 caller(`createCallerFactory`)没有请求上下文,`getRequestHeaders()` 会抛 ⇒ 加了登录校验之后
**每个测试都会 401**。解法是让 caller 自己注入:

```ts
export const TEST_USER = { id: "test-admin", name: "测试管理员", isSuper: true };
export const caller = createCallerFactory(trpcRouter)({ user: TEST_USER });
export const anonymousCaller = createCallerFactory(trpcRouter)({ user: null });   // 用来断言"必须被拒"
```

⚠️ `isSuper` 不是后门:HTTP 入口(`api.trpc.$.tsx`)**没有 `createContext`** ⇒ `ctx.user` 永远是
`undefined` ⇒ 注入这条路**从网络不可达**;它只免掉测试里"造角色 + 授权"的样板。`anonymousCaller` 则让
"未登录必须被拒"第一次变得**可测**。

## 三、审计记什么、不记什么

| 记 | 不记 |
| --- | --- |
| 所有 **mutation**(成功 status=1 / 失败 status=0)| 所有 **query** —— 否则列表翻页、缩略图签名会把日志淹掉 |
| 操作人 id + **姓名快照**(账号被删后日志仍读得懂)| 明文凭据 —— `input` 走 `logger.sanitize()`(密码等字段一律 `***`)|
| `traceId`(与 stdout 日志**同值**,一次调用能串成时间线)| 超过 2000 字符的入参快照(截断)|
| 耗时 / IP / 错误码 | 参数键以 `page.` 开头的写入(列顺序 / 树展开态属高频 UI 偏好,见 `log.skip_paths`)|

**目标描述是"尽力而为"**:`describeTarget()` 从入参里挑 `id / ids / key / code / objectKey / email / name`。
要做到"删了哪个文件"这种精确记录,得让每个 resolver 自己标注 —— 那会丢掉"零改动挂上去"这个最大好处,
所以边界就停在这里;要精确检索时看 `input` 快照。

审计是 **fire-and-forget**(`void writeAudit(...)`,写失败只打一条 stdout warn):业务永远不等审计,
审计也永远不影响业务。

## 四、权限:tRPC 路径 → 权限码的一张表

```ts
export const PERM_BY_PATH = { "file.presign": "sys:file:upload", "role.create": "sys:role:add", … };
export const UNMAPPED_MUTATIONS = ["notice.read", "notice.readAll"];   // 只余两条:48 条写接口里 46 条配上了权限点
```

两条硬规矩:

1. **只登记 `sys_menu` 里真实存在的按钮权限点** —— 登记一个"没人能被授予"的码,结果是
   **已授权的账号集体失权**(这类回归实测踩过一次);
2. **新增写接口必须显式二选一**(配权限点,或进 `UNMAPPED_MUTATIONS` 写清原因)——
   由 `tests/auth.test.ts` 的**分类守卫**强制:漏了就直接红。没这道守卫,新接口会**静默放开**。

## 五、表与清理

`sys_file` 的同门(数据库 27 张表之一):`sys_log`,`id / trace_id / path / label / type / operator_id /
operator_name / ip / target / status / error_code / error_message / input / duration_ms / create_time`,
索引 `(create_time)` / `(operator_id, create_time)` / `(path, create_time)`。**只增不改**(没有 `update_time`)。

- 三个字段是**改列之后要同步四处**的老规矩(见 `doc/数据库与认证.md`);
- 清理策略由**使用方自行决定**(模板不带定时清理任务,也没有保留天数参数);
- `log.enabled` 是总开关,排查期可临时关掉。

### 5.1 业务侧的「活动日志」**不是**本台账的替代

任务闭环有自己的 `tc_log`(见 `doc/task-close.md`「活动日志」):它记的是**业务语义**
(谁把状态从 A 改成 B、谁发起了审批、驳回原因…),只服务任务详情页的「动态」。
两者的取舍**刻意相反**,别互相对齐:

| | 写的时机 | 写失败怎么办 |
| --- | --- | --- |
| `sys_log`(本台账) | 中间件统一写,**fire-and-forget** | 只打一条 `audit.write_failed` warn,**绝不影响业务** |
| `tc_log`(业务历史) | resolver 在**业务事务里**写 | **一起回滚** —— 业务成功就一定有历史 |

后果也相反:`sys_log` 允许"缺行"(所以"审计里没有 ≠ 没发生"),跨模块的"谁改了什么"只有它;
`tc_log` 不允许缺行,但**只覆盖任务闭环这一个模块**。

## 六、已知边界

- **读侧页面 `/settings/logs` 已建**(2026-09):只读台账(没有新增 / 编辑 / 删除入口)+ `log.list` 接口 +
  权限点 `sys:log:list`。列表**默认只取最近 200 条**(上限 500)—— 审计增长很快,要看得更久用搜索框收窄
  (它连着后端对 动作名 / 路径 / 目标 / 操作人 的多字段模糊匹配);
- **工具条能导出 xlsx**(列契约 `LOG_EXCEL_COLUMNS` 在 `settings-logs-table.tsx`):导出的是**屏幕上这批**
  (当前筛选结果,不是全部历史)—— 所以 `status` 出「成功 / 失败」、时间出本地 `YYYY-MM-DD HH:mm`,
  与表格显示一致。要更久的历史,先用搜索收窄再导(`xlsx` 只在点导出时下载,不进台账页主 chunk);
- **登录 / 登出日志已接**(2026-09):BA 的 `/api/auth/*` 不走 tRPC,所以在 `src/routes/api/auth/$.ts`
  里包了一层 handler —— `auth.ok`(info)/ `auth.failed`(warn)/ `auth.err`(error),字段 `endpoint`
  (`auth.sign_in` / `auth.sign_out` / 其余按路径拼)、`method`、`path`、`status`、`ms`,登录时另带 `email`。
  **不记请求体**(密码一个字节都不进日志),`get-session` / `session` 轮询直接跳过 —— 每次页面加载都调,
  记出来只会把别的日志淹掉;
- **`UNMAPPED_MUTATIONS` 只剩两条**(见 §四):48 条写接口里 46 条配上了 `sys:*` 权限点,
  余下 `notice.read` / `notice.readAll` 属于"天生自限范围"(SQL 里一律取 `ctx.user.id`)。新接口要么配权限点、
  要么带原因进这张表,由 `tests/auth.test.ts` 的分类守卫盯着。

## 七、日志字典(调试时按 `event` 搜)

审计台账是"谁改了什么",stdout 日志是"**这一路上发生了什么**"。两者不要混:读接口不进台账,
但一定有日志。日志是单行 JSON 写 stdout,`grep '"event":"trpc.err"'` 或按 `traceId` 串起一次完整调用。

**三个保留名:`ts` / `level` / `event`** —— 字段里再传同名的键会被日志自己的值盖掉(不要拿它们当业务字段名;
实测踩过:认证端点想记 `auth.ok`,入参里的 `event: "auth.sign_in"` 把它顶掉了)。

| event | 级别 | 什么时候 | 关键字段 |
| --- | --- | --- | --- |
| `trpc.start` | debug | 每次 tRPC 调用入口 | `traceId` `path` `type` `input`(已脱敏) |
| `trpc.ok` | info | 调用成功(含耗时) | `traceId` `path` `type` `ms` |
| `trpc.slow` | warn | 超过 `LOG_SLOW_MS`(默认 1500) | `traceId` `path` `type` `ms` |
| `trpc.err` | error | 调用失败 —— **全站"为什么报错"的第一现场** | `traceId` `path` `code` `message` `ms`;同一个 `traceId` 也挂在抛出的 error 上 |
| `auth.ok` / `auth.failed` / `auth.err` | info / warn / error | BA 的 `/api/auth/*`(不走 tRPC,单独包了一层) | `endpoint` `method` `path` `status` `ms` `email`(仅登录) |
| `impersonate` | info | 管理员切换身份成功 | `from` `to`(姓名 + 邮箱快照) |
| `casbin.load` | debug | 功能权限策略装载完毕(30 秒缓存,过期才重装) | `pRows` `subjects` |
| `casbin.menu_missing` | warn | 策略行指向的菜单**已不存在**(跳过该行,不报错) | `count` `menuIds` |
| `storage.failed` | warn | MinIO 签名 / 探测 / 删除失败(之后照常抛错) | `op` `bucket` `objectKey` `message` |
| `audit.write_failed` | warn | 审计写库失败(审计绝不抛,只留一条) | `path` `message` |
| `notice.write_failed` | warn | 站内通知写库失败 | `userId` `message` |
| `db.dialect` / `dm.login_encrypt_on` / `dm.login_encrypt_defaulted` / `dm.no_schema_param` | info / warn | **启动时**打印当前方言与达梦连接参数检查(不碰数据库,只在装配驱动时) | `dialect` `target` / `hint`(人话提示) |

全仓 `grep -rhoE 'logger\.(debug|info|warn|error)\("[^"]+"'` 加低层 `log("级别", "事件名")` 去重后一共 **17 个事件**(上表全覆盖)—— 加新事件时顺手补进这张表、这个数也要跟着改。
(2026-09 行级数据权限整体删除时,`policy.*` 那 **13 个**事件名一起消失:`policy.load` / `rule_invalid` / `disabled` / `denied` / `scope` / `grant` / `ensure` / `update` / `remove` / `update_many` / `revoke_user` / `revoke_rows` / `revoke_row`;同一轮补进了 `casbin.load` / `casbin.menu_missing`。) **「多行写法」也要用跨行 grep 复核** —— 单行 grep 只数得到 13 个 `logger.*`,事件名被格式化到下一行时会漏。`casbin.*` / `dm.*` 这些用前缀 `grep -c '"event":"casbin'` 对着 stdout 抽查最省事。

配套**覆盖率用例**在 `tests/logging.test.ts`,「所有后端调用都有日志」不靠 resolver 记得加:

- 遍历路由树里**每一个** procedure(当前 105 个),无身份调一次,断言它留下 `trpc.start` + `trpc.err`
  且两者同一个 `traceId` —— 漏挂中间件就直接红(数量变了要顺手改 `EXPECTED_PROCEDURES`,提醒新接口必须走同一个工厂);
- 成功 / 慢调用阈值 / 级别过滤(debug 被 `LOG_LEVEL=info` 滤掉而 ok 还在)/ 入参脱敏 / 保留名 / traceId 挂到错误对象 各一条。
  tRPC v11 的 `.use()` 存的是包装函数,`=== loggingMiddleware` 恒假,所以断言走"真调一次看日志",不做同一性比较。

> 排查姿势:先 `grep '"level":"error"'` 找现场,再拿那行的 `traceId` 把同一次调用的 `trpc.start` / `trpc.ok` 串起来;
> 权限问题看 `casbin.load`(这轮装了哪些策略、几个主体)与 `casbin.menu_missing`(有授权指向了已经不存在的菜单)。
