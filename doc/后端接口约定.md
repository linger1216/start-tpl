# 后端接口约定(tRPC)

> 定位:这份文档回答「加一个接口 / 改一个接口时,怎么算合格」。
>
> **2026-09 重写**:模板的业务代码已清空,原先的例子(建档 / 融合 / 库表同步)随业务一起删掉了。
> 下面出现的数字与接口名都来自一次**全量实测** —— 直接读 `trpcRouter._def.procedures`(办法见第七节),
> 不是估的:**11 个 router / 65 个 procedure = 23 个 query + 42 个 mutation**。

## 一、每个接口都要能回答「它为什么单独存在」

写新接口前先自问:它是不是**另一个接口的另一种投影**?如果是,优先加参数而不是加接口。三条判据:

1. **不同粒度 = 可以有两个接口**(向导先「读清单」、再「读一条」是两次人机交互);
2. **同一份数据的两种视图 = 一个接口 + 参数**(执行日志按 `path` / `operatorId` / `status` / 时间段 / 关键词过滤,不要拆成 `log.listByPath` / `log.listByOperator` / `log.listFailed`);
3. **只有「批」与「单」两种语义**时,给**批**一个正经接口,不要让前端循环调单条 —— 见第三节。

## 二、一条业务逻辑只允许一个实现(落地口径)

| 事情 | 唯一实现 | 谁在用 |
| --- | --- | --- |
| 数据库连接(MySQL / 达梦按 env 切换) | `db`(`src/db/index.ts`) | 所有 router 与 `scripts/*` |
| 落审计行 | `lib/audit.ts` 的 `writeAudit` | 中间件自动调,**不要手写第二处** |
| 时间格式化 | `lib/time.ts` | 全部(禁止把 `toISOString()` 直接给人看) |
| 系统参数读写 + 缓存 | `lib/sys-para.ts`(`PARA_DEFAULTS` / `clearParaCache`) | `para.*`、`usePageSize()` |
| 参数类型码与校验 | `lib/para-spec.ts` | `para.update` 与参数页表单 |
| id 生成 | `lib/ids.ts`(`newId` / `formatCode`) | 建行的每个 router |
| 权限码判定 | `lib/rbac.ts`(`permMatches` / `PERM_BY_PATH`) | 中间件、路由守卫、前端 `use-perms` |
| 页面可视性判定 | `routes/(main)/route.tsx` 的 `beforeLoad` | 见 `doc/rbac-权限模型.md` |
| 通知落库 / 已读 | `lib/notice.ts` | `notice.*`、顶栏通知中心 |
| 存储(上传 / 签名 URL) | `lib/storage.ts` + `lib/storage-minio.ts` | `file.*`、头像上传 |

**判据**:同一段逻辑如果在两个接口里各写了一遍,`grep` 一下就会出现两处相似代码 —— 那时不是「复制粘贴方便」,而是「以后必然有人只改一处」。

## 三、批与单:能批就批

- 当前的批接口(实测):`policy.remove`(按 `ids` 一次删)、`menu.reorder` / `department.reorder`(整棵树的顺序一次写回)、`role.setMenus`(一次覆盖某角色的菜单集合)、`file.confirm`(一次确认一批已上传对象)。
- 前端**禁止** `for (const id of ids) await remove({ id })`:N 次往返、N 条审计,中途失败还会留下「删一半」,审计也回答不了「这次到底删了哪些」。
- 批量接口都要有上限:`.max(...)` 在 routers 里出现 **117 次**;当前最严的一处是 `policy.create` 的叉积(`subjectIds` ≤ 200 × `scopeIds` ≤ 50,展开后 > 200 条直接 `BAD_REQUEST`)。

## 四、列表接口的形状(实测,刻意不统一)

| 形状 | 接口 | 说明 |
| --- | --- | --- |
| **裸数组** | `user.list`、`role.list`、`tag.list`、`policy.list`… | 目录型表:一次取完、界面自己分页(`usePageSize()` 读 `sys_para` 的 `page.size`,当前 20) |
| **裸数组 + `limit`** | `log.list`(`limit` 默认 200、上限 500) | 「取最近的 N 条」语义,**不返回 `total`** —— 日志页不需要翻到第 9 页 |
| **`{ rows, perms }`** | `menu.list`、`menu.mine` | 菜单树 +「这个人有哪些权限码」一次给全,界面两份都要 |
| **`{ total, items }`** | `tag.objectsOfTag`(全仓唯一) | 标签 ↔ 对象的关系行可能很多,所以带 `limit` / `offset` 并真算一次 `count(*)` |

规则:**同一个接口不允许一半分页一半不分页**。目录型表真长到几百行以上,再升级成带 `total` 的分页形状。

## 五、刻意保留的「看起来重复」(别删)

| 保留项 | 为什么 |
| --- | --- |
| `para.list` 与 `para.byKey` | 前者是「代码默认值 + 库里覆盖值」的合并清单(参数页要看全字段),后者只取一条(侧边栏只关心一个界面偏好),避免为一条值拉全表 |
| `dict.list` 与 `dict.byCode` | 同上:字段管理页要全量,业务页只要一个码 |
| `menu.list` 与 `role.menuIds` | 前者是菜单树本身,后者是「某个角色已勾了哪些」(授权弹窗回填) |
| `role.list` 与 `role.users` | 前者是角色目录,后者是「这个角色下面有哪些人」 |
| `tag.list` 与四个正反查(`objectIdsOfTag` / `tagsOfObject` / `tagIdsOfObject` / `objectsOfTag`) | 同一张关系表,四个页面从不同方向读:`*OfTag` 是「先选标签再看对象」,`*OfObject` 是「先看对象再算标签」 |
| `file.presign` / `file.confirm` / `file.url` | 上传三步各自一次人机交互:要签名 → 传完确认落库 → 取预览链接;`url` 单独存在是因为预览不该再签一次名 |
| `notice.read` 与 `notice.readAll` | 点一条已读 / 全部已读,是两个动作 |

**约定**:新增「看起来重复」的接口时,把理由写进这张表;写不出理由,就合并。

## 六、权限与审计:每个 procedure 都要分类(有测试拦)

两条中间件链(`src/integrations/trpc/init.ts:182-188`):

```ts
export const publicProcedure = t.procedure.use(loggingMiddleware).use(auditMiddleware);
export const protectedProcedure = t.procedure
	.use(loggingMiddleware)
	.use(requireUser)
	.use(auditMiddleware)
	.use(permMiddleware);
```

- **写接口**:必须在 `src/lib/rbac.ts` 的 `PERM_BY_PATH` 里给出权限点(`sys:<域>:<动作>`),否则 `tests/auth.test.ts` 直接失败;
- **读接口**:三选一 —— 换成页面合成码、写进 `UNMAPPED_QUERIES`(并写清理由)、或给一个数组(任一命中即放行);
- `UNMAPPED_MUTATIONS` 现在只剩 `notice.read` / `notice.readAll`(它们是 mutation,但任何登录用户都该能调);
- **写接口自动落一条审计**(`sys_log`);批接口也是**一条请求一条**;
- 改了接口数量要同步两处:`tests/logging.test.ts` 的 `EXPECTED_PROCEDURES`(当前 **71**)与 `doc/审计日志.md`;
- 页面级拦截、失败关闭(未命中 ⇒ `1 = 0`)、「没权限为什么返回 404 不是 403」见 `doc/rbac-权限模型.md`。

## 七、自检清单(改完接口对一遍)

1. `pnpm typecheck` / `pnpm check` 0 error;
2. 权限分类(第六节)+ 审计计数同步;
3. 动过表 / 索引:`pnpm db:sync:meta`(**幂等**,第二次必须打印「无需改动」);
4. 全量回归:`pnpm test`(15 个套件);
5. 换库相关的改动先看 `doc/达梦支持.md` —— 例如 datetime 默认值必须写 `.$defaultFn(() => new Date())`,不能用 `defaultNow()`(达梦下会差 8 小时)。

数 procedure 的实测办法(新增接口后对一次):

```ts
// scripts/__probe__proc.ts —— 用完即删(约定见 AGENTS.md)
import { trpcRouter } from "../src/integrations/trpc/router.ts";

const procedures = (trpcRouter as unknown as { _def: { procedures: Record<string, { _def: { type?: string } }> } })._def
	.procedures;
const byType: Record<string, number> = {};
for (const path of Object.keys(procedures)) {
	const type = procedures[path]._def.type ?? "?";
	byType[type] = (byType[type] ?? 0) + 1;
}
console.log(Object.keys(procedures).length, byType);
```

```bash
pnpm exec dotenv -e .env.local -- node --import tsx scripts/__probe__proc.ts
```

## 八、并发与缓存(现状)

- **多表写入用事务**:`db.transaction(...)` 实测只出现在 5 个 router(`menu.ts` / `role.ts` / `user.ts` / `department.ts` / `tag.ts`),都是「主表 + 关联表一起改」的场景;
- **读缓存**:系统参数走 `lib/sys-para.ts` 的 `clearParaCache()`;功能权限策略走 `lib/casbin.ts` 的 `clearCasbinCache()`(菜单增删改后必须调);
- **不再有进程内单道队列**:那套(`lib/fusion-lane.ts` + `runInFusionLane`)是为已清空的「建档 / 融合」业务写的,文件已随业务删除 —— 新业务若需要排队,先读 `doc/已知陷阱.md`;
- **跨库**:刻意不用 `SELECT ... FOR UPDATE` / `GET_LOCK` 这类方言相关的并发原语,需要原子性就用事务;换库清单见 `doc/达梦支持.md`。
