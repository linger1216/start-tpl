# 通知中心(sys_notice + 顶栏铃铛)

站内通知,精简版:**顶栏铃铛有未读数 → 点开看最近 10 条 → 点一条就标记已读并跳到它指的页面**。

**明确不做**(所以它才精简):独立通知页、WebSocket/SSE 实时推送、邮件、通知分组与免打扰、桌面通知 API。

## 一、数据:一张表,没有附带表

| 列 | 说明 |
| --- | --- |
| `id` | nanoid |
| `user_id` | **收件人** —— 一条通知只属于一个人 |
| `title` / `body` | 标题(必填,一行字)/ 可选正文 |
| `path` | 点击跳转的**站内路径**(如 `/settings/files`),可为空 |
| `level` | `info` / `success` / `warn` / `danger` —— 决定图标与颜色 |
| `read_at` | **null = 未读** |
| `create_time` | |

索引:`(user_id, read_at, create_time)` —— 未读数与"我的最近 N 条"都吃它。

**关键简化**:「一条通知 = 一个收件人」⇒ **读态就是这一列** ⇒ 零附带表、零联合查询。
代价是群发要 N 行(`notifyMany` 就是循环);真要做"一条记录发给所有人 + 每人一份已读"再演进。

## 二、接口:3 个过程,全都只碰自己的

| 接口 | 返回 |
| --- | --- |
| `notice.list()` | `{ items: 最近 10 条, unread: 未读数 }` ← **一次请求把铃铛要的两样都给全** |
| `notice.read({ id })` | `{ ok }` |
| `notice.readAll()` | `{ updated }` |

`user_id` **一律取 `ctx.user.id`**(由 `protectedProcedure` 的中间件注入),**从不接受前端传来的用户 id** ——
所以"看别人的通知 / 改别人的已读"在 **SQL 层就不可能**,而不是靠前端不显示。
`tests/notice.test.ts` 用第二个 caller 把这条钉死了。三个过程都要求登录(未登录 ⇒ `UNAUTHORIZED`)。

## 三、发送:`lib/notice.ts` 的两个函数

```ts
await notify(userId, { title, body?, path?, level? });     // 单发
await notifyMany(userIds, payload);                        // 群发 = 循环插行
```

**为什么不开公开的创建接口**:站内通知不该被前端随便造 —— 发通知是**业务动作**(审批过了、任务跑完了、被指派了),
在那一刻由服务端代码调 `notify()` 即可。要给管理员一个"手动发"的入口时,再加一个带权限点的接口。
两个函数都 **`try/catch` 吞错**(同 `writeAudit`):通知失败不能影响业务。

演示数据:`pnpm db:seed:notices`(幂等,给每个**还没通知**的账号补 3 条,其中一条带 `path`)。

## 四、`path`:写入时关门 + 点击时兜底

```ts
/^\/(?!\/)[A-Za-z0-9\-/_.\[\]]*$/   // 单个 / 开头、只含路径安全字符
```

⚠️ **`(?!\/)` 不能省**:`//evil.example/x` 也满足「以 `/` 开头 + 只含安全字符」,但浏览器把它当**外部主机** ——
那是一条**开放跳转**。这条是**测试用例抓出来的**(第一版正则就漏了它)。

点击时:`read({ id })` → 有 `path` 就 `router.navigate({ to: path as never })`,**外面包 try/catch** ——
路径失效时给一句 toast 而不是白屏(数据可以携带 path,写入的校验挡的是"脏路径",挡不住"目标页面以后被删")。

## 五、顶栏:只改那颗铃铛

`components/layout/notification-bell.tsx`,顶栏里一行 `<NotificationBell />`。

- **未读数是品牌色药丸(1–9 / `9+`)**,不是告警红 —— 未读不是告警,告警语义只留给 `success/warn/danger`;
- 面板与右端**用户菜单同一个组件、同一个 `align="end"`**,触发器用 `render={<Button variant="ghost" size="icon" … />}`
  (与 `user-switcher` 同款写法)—— 顶栏两个下拉天然同形;
- **点击先标已读再跳**,所以数字立刻减 1;未读左侧有一根品牌色竖条,已读留同样宽度的空位(两行文字才不会错位);
- 刷新:`useQuery` + **60 秒轮询** + 操作后 `invalidate`。够用、无长连接;真需要实时再上 SSE。

## 六、已知边界

- 面板只显示**最近 10 条**(要全量就加一个"所有通知"页 + 分页);
- **轮询**不是推送(60 秒);
- **群发是 N 行**(见上);
- 没有"通知偏好 / 免打扰"。

## 七、批量发与管理入口(2026-09 加)

- **`notice.create({ userIds, title, body?, path?, level? })`** —— 给**别人**发,需要 **`sys:notice:add`**:
  权限码登记在 `lib/rbac.ts` 的 `PERM_BY_PATH`,按钮由 `scripts/seed-rbac.ts` 建在「我的通知」菜单下。
  **没这个权限的人在服务端被拒**(`tests/auth.test.ts` 的 FORBIDDEN 用例钉住),前端只是不显示入口。
- **「我的通知」整页(`/notices`,根菜单)**:与其它台账页同形的**只读**台账 —— 统计卡 ×3(全部 / 未读 / 已读)、
  搜索、列开关、分页、行内「打开」;**没有新增、没有删除**(行内也没有删除入口)。
  行内「打开」在**没有 `path` 的行上禁用**(而不是隐藏 —— 藏了会让人以为没这个功能)。
- **页头主操作顺序**:刷新(纯图标)→ 全部已读(`outline`,未读为 0 时置灰)→ 发通知(有权限才渲染)。
- 列表用 `notice.list({ limit: 500 })`(接口上限 500),拉回客户端分页 —— 与其它台账页同口径。

### 一条实测反馈带来的修正

铃铛面板里的「全部已读」原来**只在有未读时渲染**,于是"读完之后它就消失了",用户以为没有这个功能。
现在**常驻**,未读为 0 时**置灰**。「一个动作只要在哪些情况下可用,它的入口就应该一直看得见」——
这条与树的行尾图标(「可辨认的入口就得在哪些行出现」)是同一个道理。
