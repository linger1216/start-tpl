# 容器化(Docker / Compose / Dev Container)

一套 compose 覆盖三种用法:**本机一键起全栈**、**初始化任务**(建表 / 种子 / 建桶)、**Dev Container**。

> 设计口径:**一份环境定义,不维护第二份**。`docker-compose.yml` 是唯一事实来源,devcontainer 只是
> 叠加一层(多挂一个工作容器);镜像只负责"能跑起来",不塞 CI/CD;运行镜像**必须能独立启动** ——
> 为此宁可多装一份生产依赖(见 §四)。

---

## 一、三条命令起步

```bash
cp .env.example .env.local                            # 至少填 BETTER_AUTH_SECRET
docker compose --profile setup run --rm bootstrap     # 建 19 张表 + 四个种子 + 建 MinIO 两个桶
docker compose up -d                                  # http://localhost:3000
```

| 命令 | 说明 |
| --- | --- |
| `docker compose up -d` | 起 mysql(宿主 **3307**)+ minio(9000 / 9001)+ app(3000),都只绑 `127.0.0.1` |
| `docker compose --profile setup run --rm bootstrap` | 一次性初始化,**幂等**,可随便重跑 |
| `docker compose --profile setup run --rm bootstrap sh -c "pnpm db:seed:demo"` | 加灌演示数据(26 个账号 + 71 条网格) |
| `docker compose logs -f app` | 看应用日志(容器里就是 `pnpm start` 的输出) |
| `docker compose exec app sh` | 进应用容器 |
| `docker compose down` / `down -v` | 停容器 / 连数据卷一起清掉 |

`bootstrap` 用的是 dev 镜像(要跑 tsx 脚本),跑完即退,`up -d` 不会带上它 —— 这就是它被放进
`setup` profile 的原因。

## 二、四个服务 + 一个 profile

| 服务 | 来自 | 端口(宿主) | 干什么 |
| --- | --- | --- | --- |
| `mysql` | `mysql:8.4`(可覆盖) | 3307 → 3306 | 库;`utf8mb4` / `utf8mb4_0900_ai_ci` |
| `minio` | `minio/minio:latest` | 9000(API)/ 9001(控制台) | 对象存储;桶由 bootstrap 里的 `pnpm db:minio:init` 建 |
| `app` | `Dockerfile` target `runtime` | 3000 → 3000 | 生产产物 `.output` + `node --import instrument.server.mjs` |
| `bootstrap` | `Dockerfile` target `dev`(profile `setup`) | — | 建表 + 种子 + 建桶;幂等 |
| `dev` | `Dockerfile` target `dev`(在 `docker-compose.dev.yml`) | 3000 → 3000 | Dev Container 的工作容器,`sleep infinity` |

`app` 等 `mysql` / `minio` 的 **healthcheck 通过**才启动;`bootstrap` 同理。

## 三、可覆盖的变量

`docker compose` **只自动读根目录的 `.env`**;应用自己的 `.env.local` 是用 `env_file` 显式喂进去的
(文件不存在也不报错 —— 那样应用会以「缺 `DATABASE_URL`」这类明确错误退出,而不是带着半份配置跑起来)。

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `APP_PORT` | `3000` | 应用宿主端口。**改了要同步** `BETTER_AUTH_TRUSTED_ORIGINS`(代码内置只认 `http://localhost:3000`) |
| `MYSQL_IMAGE` | `mysql:8.4` | 本机开发用的是 **9.1**;想完全对齐:`MYSQL_IMAGE=mysql:9.1 docker compose up -d` |
| `MYSQL_PORT` | `3307` | 避开宿主机上可能已占用的 3306 |
| `MYSQL_ROOT_PASSWORD` | `tpl-local-root` | 只用于本机;`app` 的 `DATABASE_URL` 由它拼出来 |
| `MYSQL_DATABASE` | `eg` | 库名 |
| `MINIO_IMAGE` | `minio/minio:latest` | |
| `MINIO_API_PORT` / `MINIO_CONSOLE_PORT` | `9000` / `9001` | `MINIO_PUBLIC_URL` 跟着 API 端口拼 |
| `MINIO_ROOT_USER` / `MINIO_ROOT_PASSWORD` | `minioadmin` | 同步喂给 `MINIO_ACCESS_KEY` / `MINIO_SECRET_KEY` |
| `MINIO_BUCKET_PUBLIC` / `MINIO_BUCKET_PRIVATE` | `app-public` / `app-private` | 公开桶走直链,私有桶走预签名 |
| `DEV_PORT` | `3000` | 仅 `docker-compose.dev.yml` |

## 四、Dockerfile 的四个目标

| target | 内容 | 用途 |
| --- | --- | --- |
| `deps` | `pnpm install --frozen-lockfile`(含 devDependencies) | 给下面两个目标复用,只拷 `package.json` + 锁文件 |
| `build` | 源码 + `pnpm build` → `.output` | 出 Nitro 产物 |
| `dev` | 源码 + 全部依赖 + `git`,CMD `pnpm dev` | Dev Container / bootstrap 脚本 |
| `runtime` | `.output` + `pnpm install --prod`(默认目标) | 生产 |

三个关键决定:

1. **运行镜像里必须再装一次生产依赖。** Nitro 的 node-server 产物**不是自包含的**:
   `pnpm build` 最后一步 `cp instrument.server.mjs .output/server` 是**原样拷贝、不过打包器**,而那个
   文件第一行就是 `import * as Sentry from '@sentry/tanstackstart-react'`。只 `COPY .output` 的镜像
   启动即崩:
   ```
   Error [ERR_MODULE_NOT_FOUND]: Cannot find package '@sentry/tanstackstart-react'
   imported from .output/server/instrument.server.mjs
   ```
   `.output/server` 下没有 `node_modules`,应用代码都进了 `_libs` / `_chunks` / `_ssr`。
2. **构建期不需要任何机密或占位值。** `vite build` 不会评估 `src/db/index.ts` —— 在**没有** `.env.local`、
   **没有** `DATABASE_URL` 的仓库副本里构建成功(exit 0,产 `.output/nitro.json`)。
3. **不把 `.env.local` 烤进镜像**:`VITE_*` 会被编译进前端产物,机密不该进镜像;运行期环境变量由
   `docker run -e` / compose 注入(`pnpm start` 本来就不读任何 env 文件)。

base 用 `node:22-bookworm-slim`(glibc)。`dmdb` 是纯 JS(无 `.node` 原生二进制),理论上 alpine 也能跑,
但 glibc 更省心。healthcheck 用 node 自带的 `fetch` 打 `/api/auth/ok`(Better Auth 的健康检查,不需要
登录,实测 `{"ok":true}` / 200),不额外装 curl。

## 五、Dev Container

VS Code →「Dev Containers: Reopen in Container」。起 `dev` + `mysql` + `minio`(不会去建生产镜像)。

- 仓库**绑定挂载**到 `/app`,`node_modules` 与 pnpm store 单独放**命名卷** —— 不把宿主的依赖带进容器,
  也避开 macOS 绑定挂载的 I/O 拖慢 vite。
- `postCreateCommand: pnpm install`(命名卷首次是空的)。
- 转发 `3000 / 3307 / 9000 / 9001`(映射同时写在 compose 里,所以宿主机上本来就通)。
- 容器里 `pnpm dev` 默认只监听容器内 localhost;VS Code 的端口转发连的就是容器内地址,所以能直接用。
  直连(`docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d dev`)时才需要
  `pnpm dev --host 0.0.0.0`。

## 六、踩过的坑 / 已知缺口

| 现象 | 原因 / 处理 |
| --- | --- |
| 只 COPY `.output` 启动即 `ERR_MODULE_NOT_FOUND` | 见 §四.1:运行镜像要带生产依赖 |
| 容器里 `pnpm install` 去写 `/Users/xxx/...` | 本地 `.npmrc` 写着 `store-dir=<宿主机绝对路径>`。已 `.dockerignore` 排除,并在镜像里强制 `npm_config_store_dir=/pnpm/.data/pnpm/store` |
| 镜像 tag 没法在本机核实 | registry 出口被重置:`failed to configure transport: error pinging v2 registry: … read tcp [2409:…]: connection reset by peer`(IPv6)。所以 MySQL 默认取久经考验的 **8.4 LTS**,本机开发实际是 **9.1.0** |
| `docker build` / `up` **未实测** | 本机 Docker daemon 没起(OrbStack 未运行,`unix:///Users/lid/.orbstack/run/docker.sock` 连不上)。已做的是:① `docker compose config` 离线校验(exit 0,插值后的 `DATABASE_URL` / 端口 / healthcheck / bootstrap 命令逐条核过);② 把 `.output` 拷到 `/tmp` + 软链宿主 `node_modules` 直接跑生产产物 —— `/` 307、`/api/auth/ok` 200、`POST /api/auth/sign-in/email` 200 |
| 日志里 `Rate limiting could not determine a client IP and is falling back to a single shared per-path bucket…` | Better Auth 取不到真实客户端 IP。compose 直连(端口映射)时取到的是容器网关地址,本机可忽略;放到反向代理后要在 `src/lib/auth.ts` 配 `advanced.ipAddress.ipAddressHeaders` / `trustedProxies` |
| 达梦 | compose 只给 MySQL。换 `DATABASE_URL=dm://…` 并让容器能访问达梦即可(模板不含达梦镜像;差异见 `doc/达梦支持.md`) |

## 七、验收清单

- `docker compose config` → exit 0;`--services` 出 `mysql / minio / app`;`--profile setup` 多出 `bootstrap`
- `docker compose -f docker-compose.yml -f docker-compose.dev.yml config` → exit 0,`dev` 挂载是
  `<仓库>:/app` + `dev-node_modules:/app/node_modules` + `dev-pnpm-store:/pnpm/.data`
- `.env.local` 不在构建上下文里(`.dockerignore`),构建产物里没有机密
- 离线模拟 build 阶段:把仓库(去掉 `node_modules` / `.output` / `.env.local` / `.npmrc`)拷到 `/tmp` 后
  `vite build` → exit 0;把 `.output` 拷走、只软链宿主 `node_modules` 直接 `node --import` 启动 →
  `/` 307、`/api/auth/ok` 200
- 起了 daemon 之后:`bootstrap` 连跑两次仍全「已存在 / 不存在,跳过」;`curl 127.0.0.1:3000/api/auth/ok`
  回 `{"ok":true}`;`POST /api/auth/sign-in/email` 用 `admin@example.com` / `Passw0rd123` 回 200
