# 容器化(Docker / Compose)

一个 `docker-compose.yml` 覆盖两种用法:**本机一键起全栈**、**初始化任务**(建表 / 种子 / 建桶,profile `setup`)。

> 设计口径:**一份环境定义,不维护第二份**。`docker-compose.yml` 是唯一事实来源,靠 profile 按需启停
> (初始化任务 `bootstrap` 挂在 profile `setup` 下)。镜像只负责"能跑起来",不塞 CI/CD;运行镜像
> **必须能独立启动** —— 为此宁可多装一份生产依赖(见 §四)。

---

## 一、三条命令起步

```bash
cp .env.example .env.local                            # 至少填 BETTER_AUTH_SECRET
docker compose --profile setup run --rm bootstrap     # 建 34 张表 + 四个种子 + 建 MinIO 两个桶
docker compose up -d                                  # http://localhost:3000
```

| 命令 | 说明 |
| --- | --- |
| `docker compose up -d` | 起 mysql(宿主 **3307**)+ minio(9000 / 9001)+ app(3000),都只绑 `127.0.0.1` |
| `docker compose --profile setup run --rm bootstrap` | 一次性初始化,**幂等**,可随便重跑 |
| `docker compose --profile setup run --rm bootstrap sh -c "pnpm db:seed:demo"` | 加灌演示数据(71 条网格;README 提到的 26 个演示账号是本机手工准备的,种子脚本不建) |
| `docker compose logs -f app` | 看应用日志(容器里就是 `pnpm start` 的输出) |
| `docker compose exec app sh` | 进应用容器 |
| `docker compose down` / `down -v` | 停容器 / 连数据卷一起清掉 |

`bootstrap` 用的是 dev 镜像(要跑 tsx 脚本),跑完即退,`up -d` 不会带上它 —— 这就是它被放进
`setup` profile 的原因。

## 二、五个服务 + 一个 profile

| 服务 | 来自 | 端口(宿主) | 干什么 |
| --- | --- | --- | --- |
| `mysql` | `mysql:8.4`(可覆盖) | 3307 → 3306 | 库;`utf8mb4` / `utf8mb4_0900_ai_ci` |
| `minio` | `rustfs/rustfs:1.0.3` | 9000(API)/ 9001(控制台) | S3 兼容对象存储;桶由 bootstrap 里的 `pnpm db:minio:init` 建 |
| `app` | `Dockerfile` target `runtime` | 3000 → 3000 | 生产产物 `.output` + `node .output/server/index.mjs` |
| `worker` | `Dockerfile` target `worker` | — | 独立调度与通知投递进程 |
| `bootstrap` | `Dockerfile` target `dev`(profile `setup`) | — | 建表 + 种子 + 建桶;幂等,跑完即退 |

`app` 等 `mysql` / `minio` 的 **healthcheck 通过**才启动;`bootstrap` 同理。

## 三、可覆盖的变量

`docker compose` **只自动读根目录的 `.env`**;应用自己的 `.env.local` 是用 `env_file` 显式喂进去的
(文件不存在也不报错 —— 那样应用会以「缺 `DATABASE_URL`」这类明确错误退出,而不是带着半份配置跑起来)。

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `APP_PORT` | `3000` | 应用宿主端口。**改了要同步** `BETTER_AUTH_TRUSTED_ORIGINS`(代码内置只认 `http://localhost:3000`) |
| `MYSQL_IMAGE` | `mysql:8.4` | 本机开发用的是 **9.1**;想完全对齐:`MYSQL_IMAGE=mysql:9.1 docker compose up -d` |
| `MYSQL_PORT` | `3307` | 避开宿主机上可能已占用的 3306 |
| `MYSQL_ROOT_PASSWORD` | `tpl-local-root` | 只用于本机;`app` 的 `DATABASE_URL` 由它拼出来 |
| `MYSQL_DATABASE` | `eg` | 库名 |
| `OBJECT_STORAGE_IMAGE` | `rustfs/rustfs:1.0.3` | 可覆盖成其他兼容 S3 API 的对象存储镜像 |
| `MINIO_API_PORT` / `MINIO_CONSOLE_PORT` | `9000` / `9001` | `MINIO_PUBLIC_URL` 跟着 API 端口拼 |
| `MINIO_ROOT_USER` / `MINIO_ROOT_PASSWORD` | `minioadmin` | 同步喂给 `MINIO_ACCESS_KEY` / `MINIO_SECRET_KEY` |
| `MINIO_BUCKET_PUBLIC` / `MINIO_BUCKET_PRIVATE` | `app-public` / `app-private` | 公开桶走直链,私有桶走预签名 |

## 四、Dockerfile 的四个目标

四个目标都长在 `base` 这个公共底座上(`node:22-bookworm-slim` + pnpm 环境变量 + `corepack enable`)——
`deps` 与 `runtime` 各自都需要那套变量,写在 `base` 里就不必两份各养一份。

| target | 内容 | 用途 |
| --- | --- | --- |
| `base` | pnpm 环境变量 + `corepack enable`(不是给人用的目标,只给下面两个当底座) | 消掉 `deps` / `runtime` 的重复 |
| `deps` | `pnpm install --frozen-lockfile`(含 devDependencies) | 给下面两个目标复用,只拷 `package.json` + 锁文件 |
| `build` | 源码 + `pnpm build` → `.output` | 出 Nitro 产物 |
| `dev` | 源码 + 全部依赖 + `git`,CMD `pnpm dev` | `bootstrap` 初始化脚本(要 tsx) |
| `runtime` | `.output` + `pnpm install --prod`(默认目标) | 生产 |

三个关键决定:

1. **运行镜像里必须再装一次生产依赖。** Nitro 的 node-server 产物**不是自包含的**:
   应用代码都进了 `_libs` / `_chunks` / `_ssr`,但 bundle 仍是按包名 `import`,所以运行镜像里
   必须 `pnpm install --prod`(否则启动即崩 `ERR_MODULE_NOT_FOUND`)。
2. **构建期不需要任何机密或占位值。** `vite build` 不会评估 `src/db/index.ts` —— 在**没有** `.env.local`、
   **没有** `DATABASE_URL` 的仓库副本里构建成功(exit 0,产 `.output/nitro.json`)。
3. **不把 `.env.local` 烤进镜像**:`VITE_*` 会被编译进前端产物,机密不该进镜像;运行期环境变量由
   `docker run -e` / compose 注入(`pnpm start` 本来就不读任何 env 文件)。

4. **依赖安装要带上 `pnpm-workspace.yaml`。** pnpm 12 在这里读取 `allowBuilds`,批准 esbuild 的安装脚本；
   漏拷此文件会让生产依赖安装以 `ERR_PNPM_IGNORED_BUILDS` 失败。

base 用 `node:22-bookworm-slim`(glibc)。`dmdb` 是纯 JS(无 `.node` 原生二进制),理论上 alpine 也能跑,
但 glibc 更省心。healthcheck 用 node 自带的 `fetch` 打 `/api/auth/ok`(Better Auth 的健康检查,不需要
登录,实测 `{"ok":true}` / 200),不额外装 curl。

## 五、踩过的坑 / 已知缺口

| 现象 | 原因 / 处理 |
| --- | --- |
| 只 COPY `.output` 启动即 `ERR_MODULE_NOT_FOUND` | 见 §四.1:运行镜像要带生产依赖 |
| 容器里 `pnpm install` 去写 `/Users/xxx/...` | 本地 `.npmrc` 写着 `store-dir=<宿主机绝对路径>`。已 `.dockerignore` 排除,并在镜像里强制 `npm_config_store_dir=/pnpm/.data/pnpm/store` |
| `minio/minio:latest` 拉取失败 | MinIO 社区镜像当前无法从 Docker Hub 公共拉取。开发 Compose 默认改用 RustFS `1.0.3`(S3 兼容);生产可接入已有 MinIO 或其他兼容 S3 API 服务 |
| RustFS 控制台登录 / CORS | 控制台地址 `http://localhost:9001`;登录凭据沿用 `MINIO_ROOT_USER` / `MINIO_ROOT_PASSWORD`。桶的 CORS 仍需按 `doc/文件管理.md` 配置 |
| 本轮 Docker 验证进度 | `docker compose -p stacktpl-verify build app worker bootstrap` 已成功。随后拉取 RustFS 成功，但 MySQL 镜像下载过程中 Docker daemon / OrbStack socket 中断，`bootstrap` 尚未跑完，应用健康接口也未验证；之后需重新启动 Docker 再继续 |
| 日志里 `Rate limiting could not determine a client IP and is falling back to a single shared per-path bucket…` | Better Auth 取不到真实客户端 IP。compose 直连(端口映射)时取到的是容器网关地址,本机可忽略;放到反向代理后要在 `src/lib/auth.ts` 配 `advanced.ipAddress.ipAddressHeaders` / `trustedProxies` |
| 达梦 | compose 只给 MySQL。换 `DATABASE_URL=dm://…` 并让容器能访问达梦即可(模板不含达梦镜像;差异见 `doc/达梦支持.md`) |

## 六、验收清单

首次本机运行(需要 Docker Engine + Compose 插件):

```bash
cp .env.example .env.local
# 编辑 .env.local,设置 BETTER_AUTH_SECRET(至少 32 字符)

# ① 先验证「三个镜像能构建」(不需要起 mysql / 对象存储)
docker build --target runtime -t start-tpl:runtime .
docker build --target worker -t start-tpl:worker .
docker build --target dev -t start-tpl:dev .

# ② 建表 + 种子 + 建桶(幂等),然后起全栈
docker compose --profile setup run --rm bootstrap
docker compose up -d --build
docker compose ps
curl -fsS http://localhost:3000/api/auth/ok   # 期望 {"ok":true}
```

`bootstrap` 会临时拉起 MySQL 与 RustFS,创建表、基础种子和对象桶后退出;随后 `up` 启动 MySQL、RustFS、应用与 worker。
`docker compose logs -f app worker` 查看日志,`docker compose down` 停服务但保留数据卷。仅当确认要清空本地数据时才运行 `docker compose down -v`。

- `docker compose config -q` → exit 0;`docker compose config --services` 出 `mysql / minio / app / worker`;
  `--profile setup` 多出 `bootstrap`(Compose v5 起 `--services` 是 `config` 的子命令,不是 `compose` 的顶层 flag)
- `.env.local` 不在构建上下文里(`.dockerignore`),构建产物里没有机密
- 离线模拟 build 阶段:把仓库(去掉 `node_modules` / `.output` / `.env.local` / `.npmrc`)拷到 `/tmp` 后
  `vite build` → exit 0;把 `.output` 拷走、只软链宿主 `node_modules` 直接 `node --import` 启动 →
  `/` 307、`/api/auth/ok` 200
- Dockerfile 三个镜像目标构建成功;完整 Compose 验收待 Docker daemon 恢复后继续(见 §五)
