# 全球眼视频

> 面向维护者。协议来源:`中国电信 DSS`(`videoService/*`),由 `ChinaNetVideoHelp.java` /
> `china_net_video_help.py` 移植。页面:`/global-eye`(顶层菜单「全球眼视频」)。

## 是什么

左侧是**视频通道树**(组织 → 设备 → 通道,来自平台的 `deviceTree`),点一个通道,
右侧显示该通道的**全部字段**并提供**实时预览**(HLS `<video>`)。凭据全部走环境变量。

## 数据流

```
浏览器 ──tRPC globalEye.channelTree──▶ 服务端 lib/global-eye.ts ──HTTPS──▶ 视频平台
        ──tRPC globalEye.streamUrl ───▶  (带 token 取 HLS 地址)
浏览器 ◀── 通道字段 / 代理播放地址 ─────┘
浏览器 ──GET /api/globaleye/stream?u&s─▶ 服务端代理 ──HTTPS──▶ 平台流媒体地址
        (hls.js 拉 m3u8 与分片,全同源)     (透传 / 改写 m3u8)
```

- **凭据 / token 永不返回浏览器**:浏览器只拿到通道字段和本服务的代理地址。
- **播放走本服务代理**:平台的取流地址**不带 CORS 头**,浏览器里的 hls.js / `<video>`
  跨域读不了它的 m3u8 与分片 —— 浏览器同源策略挡不住地在前端解决,只能服务端转发。
  代理同时解决平台自签证书(服务端 `rejectUnauthorized:false` 拉取,浏览器只见本服务的证书)。

## 播放代理 `/api/globaleye/stream`

这是 AGENTS「接口只有 tRPC」的**第 4 个 REST 例外**(另三个:`/api/auth/*`、`/api/sse/notice`、
`/api/captcha`)。理由三条:

1. 需要**流式 GET**(持续拉分片、透传 206),tRPC(superjson JSON)接不住二进制流;
2. 需要在**服务端**取数绕开浏览器的跨域与自签证书;
3. 同族:与 SSE 一样是「内容协商 + 自己判身份」的端点,不是业务 CRUD。

安全边界(不能做成开放代理):

- **只转发本服务签过名的地址**:`u=<上游URL>&s=<HMAC>`(`signGlobalEyeTarget` / `verifyGlobalEyeTarget`,
  密钥取 `BETTER_AUTH_SECRET`),签名由 `globalEye.streamUrl` 下发 —— 攻击者造不出任意 `u`,杜绝 SSRF / 开放代理;
- **要求登录**(`getCurrentUser()`,未登录 401),与 `/api/sse/notice` 同口径;
- 只放行 http / https;
- 透传响应头走白名单,不带出上游的 `set-cookie` 等。

HLS 播放列表(m3u8)会被 `rewriteHlsPlaylist` **改写**:每条分片 / 子播放列表 URI、以及
`URI="…"` 属性(密钥 / 初始化段)都换成代理地址(相对地址按**重定向之后**的最终地址解析),
保证后续请求也在同源 —— 否则第一条成了、分片照样跨域。

## 协议(见 `src/lib/global-eye.ts`)

| 动作 | 接口 |
| --- | --- |
| 登录(两次握手,5 次 MD5 签名) | `POST /videoService/accounts/authorize` |
| 保活 | `PUT /videoService/accounts/token/keepalive` |
| 目录 | `GET /videoService/devicesManager/deviceTree`(typeCode 区分组织 / 设备 / 通道) |
| 取流地址 | `GET /videoService/realmonitor/uri`(scheme=HLS) |

## token 保活

- token 是**模块级单例**,并发调用共享同一次登录(`inflight` 去重);
- 首次登录成功后起一个 `setInterval` 定时 keepalive,间隔 = `GLOBALEYE_KEEPALIVE_SECONDS`(默认 120s),
  定时器 `unref()`,不阻止进程退出;
- keepalive 失败(或返回 `result !== 0`)⇒ 清空 token,下次调用自动重新登录。

> 单进程单例:多副本部署时每个副本各持一个 token(平台是否允许并发会话由平台决定)。
> 真要跨副本共享,需把 token 落到共享存储 —— 模板没预置。

## 环境变量

见 `.env.example` 的「全球眼视频」段。关键项:`GLOBALEYE_HOST` / `GLOBALEYE_PORT` /
`GLOBALEYE_USERNAME` / `GLOBALEYE_PASSWORD`;平台常是自签证书,默认 `GLOBALEYE_INSECURE_TLS=true`。

## 权限

- 读接口按**页面码** `page:global_eye:view` 放行(菜单勾上即可见),登记在 `lib/rbac.ts` 的
  `PERM_BY_PATH`;两个 query 在 `UNSCOPED_QUERIES`(读外部平台,不做行级过滤)。
- 菜单进 `sys_menu` 靠 `pnpm db:seed:menus`(在 `nav-config.ts` 的 `NAV_NODES` 里登记)。
- 没有 mutation,所以不需要按钮权限点,也不动审计词表。
- 播放代理是**普通 GET 路由**,不走 tRPC 权限中间件 —— 它的验证是「登录 + HMAC 签名」,见上。
