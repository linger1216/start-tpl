# 全球眼视频

> 维护说明。协议来源:中国电信 DSS(`videoService/*`),由 `ChinaNetVideoHelp.java` /
> `china_net_video_help.py` 移植。页面:`/global-eye`。

## 是什么

左侧**通道树**(组织 → 设备 → 通道),点通道后右侧显示其全部字段并可播放。
凭据只走环境变量,前端拿不到账号密码。

## 数据流

```
浏览器 ─tRPC channelTree─▶ 服务端 lib/global-eye.ts ──▶ 平台(authorize + deviceTree)
       ─tRPC streamUrl ──▶ 服务端取 HLS 地址
浏览器 ─hls.js 直连 m3u8─▶ 平台媒体地址(HLS 端点带 CORS)
```

- **只用 HLS**:实测平台 HLS 端点带 CORS,Chrome 用硬件解 H.265,`hls.js` 能正常出画面。
  FLV 端点的封装对 JS 解封装器不友好(只能拿到序列头、出不了帧),不用它。
- 播放地址有时效(约 10 分钟不用失效),每次播放/重试都重新取。

## 协议(`src/lib/global-eye.ts`)

| 动作 | 接口 |
| --- | --- |
| 登录(两次握手,5 次 MD5 签名) | `POST /videoService/accounts/authorize` |
| 保活 | `PUT /videoService/accounts/token/keepalive` |
| 目录 | `GET /videoService/devicesManager/deviceTree` |
| 取流 | `GET /videoService/realmonitor/uri`(scheme=HLS) |

## token 保活

token 是模块级单例;首次登录后起 `setInterval` **每 60s** 保活(`unref()`);
失败清 token,下次自动重登。页头「刷新」= 绕过缓存 + 重新登录。

## 缓存

通道树重建很慢,服务端用 `createTtlCache` 缓存(**300s**,并发去重)。

## 环境变量

只需三项(见 `.env.example`):

```
GLOBALEYE_URL=https://host:port
GLOBALEYE_USERNAME=
GLOBALEYE_PASSWORD=
```

其余全部内置:取流固定 **HLS**;码流**先子(1)后主(0)** 自动兜底;保活 60s;树缓存 300s;
平台多为自签证书,默认**不校验** TLS(`GLOBALEYE_VERIFY_TLS=1` 可开启校验)。

## 权限

两个 query 在 `PERM_BY_PATH`(页面码 `page:global_eye:view`)与 `UNSCOPED_QUERIES`;
菜单靠 `pnpm db:seed:menus`。无 mutation。

## 已知事项

- 父级字段名 best-effort(`toGlobalEyeTreeRows` 按优先级兜;解析不出父级会提升为一级)。
- 平台同一账号近似单会话:别处再次 `authorize` 会顶掉这里的 token;失败时点「刷新」重登。
- **平台偶发「`result:0` 但没有 url」**(设备/流媒体瞬时忙,或该通道没有子码流):`getGlobalEyeStreamUrl`
  会按当前码流重试 2 次,再**换另一条码流**兜底;仍无线索才报错。属平台侧瞬态,前端点「重试」即可。
- **平台偶发 m3u8 `404`**(媒体节点负载均衡到不同 IP,个别节点/该次签发不返回流):`player.tsx`
  在 hls.js 致命错误时会**自动重新取一次地址**(最多 2 次)再试。
