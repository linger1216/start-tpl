# 任务闭环插件化架构详细设计规范

> 本文档定义任务闭环中**任务数据载荷、展示形式、现场交互作答、流程模板内聚**以及**内核动态状态机操作按钮引擎**的完整解耦方案。  
> 核心目标：让内核成为纯粹的工作流与动作宿主，插件不仅承载数据与交互，还内聚贡献流程模板；内核根据不定的状态图拓扑，自动生成并驱动操作按钮。

## 2. 插件内聚流程模板（Plugin-Contributed Workflows）

### 2.1 理念转变：选流程 = 选插件
以往是先有一个孤立的流程模板，再想办法找插件适配；  
**新架构：插件即业务方案。一个插件定义自身的数据形态，并自带一套推荐的最佳实践流程模板。**

- 一个业务插件（如 `safety-inspection`）内聚定义并贡献 1 套或多套流程模版：
  - 《危化企业现场安全检查流程》（含初查 -> 整改 -> 复查闭环）
  - 《一般工贸日常巡检流程》（简化版：直接检查 -> 归档）
- 开发者编写插件时，将该业务的默认状态机一同写在插件声明里；
- 系统启动/种子初始化时，内核的 `PluginHub` 自动注册插件并将其模板同步入库（`tc_workflow`）。

### 2.2 流程模板定义契约

```ts
/** 边定义补充：动作显示文案与按钮风格 */
export type WorkflowEdgeDef = {
  from: string;
  to: string;
  who: ("creator" | "executor" | "participant" | "any")[];
  via: "direct" | "action";
  /** 按钮文字覆写（如果不填，默认展示为“推进至: [目标状态名]”） */
  actionLabel?: string;
  /** 按钮语义色调：决定渲染为 主操作 / 告警红 / 描边灰 */
  actionTone?: "default" | "danger" | "outline";
  /** 动作前置确认提示（如：“确认将该任务判定为不合格并推送到整改阶段？”） */
  confirmMessage?: string;
};

/** 插件内聚的完整模板声明 */
export type ContributedWorkflow = {
  id: string;
  name: string;
  description: string;
  initial: string;
  statuses: Array<{ value: string; label: string; tone?: string }>;
  edges: WorkflowEdgeDef[];
};
```

## 3. 内核动态操作按钮引擎（Dynamic Action Engine）

核心难点：**状态名和状态图拓扑是动态且不确定的，内核如何绝不硬编码任何状态名，却能给对按钮？**

### 3.1 按钮三大来源分类

任务详情页顶部的动作组由内核统一归并，由以下三部分动态合成：

```
┌─────────────────────────────────────────────────────────────────────────────────┐
│                          记录头操作区 (Action Bar)                                │
│                                                                                 │
│  [插件专属动作]            [拓扑流转动作 (动态推导)]           [系统通用动作]       │
│  - 一键快速合格全部        - [提交检查结果 (直转)]            - [编辑任务]         │
│  - 生成复查整改单          - [发起审批: 执法中队复核 (审批)]   - [打印报告]         │
│                                                              - [删除 / 刷新]      │
└─────────────────────────────────────────────────────────────────────────────────┘
```

### 3.2 动态流转按钮推导算法（图出边投影）

内核依据**有向图当前节点的出边（Outgoing Edges）**，实时投影出当前操作员可执行的所有流转动作：

$$\text{ActiveTransitions} = \left\{ e \in \text{task.workflow.edges} \;\middle|\; e.\text{from} = \text{task.status} \land \text{CanExecute}(e, \text{myRole}) \right\}$$

#### 判定与执行逻辑：

```ts
function computeTransitionButtons(
  task: TaskWithWorkflow,
  myRole: string | null,
  isLocked: boolean
): TransitionButton[] {
  // 1. 如果任务处于外挂动作锁定中（pending），阻断一切常规状态推进
  if (isLocked) {
    return [{
      id: "locked_hint",
      label: "审批锁定中…",
      disabled: true,
      hint: "当前存在未答复的审批动作，待答复结算后方可推进状态"
    }];
  }

  // 2. 匹配当前状态的所有可达出边
  const outgoingEdges = task.workflow.edges.filter(
    (edge) => edge.from === task.status
  );

  // 3. 按当前操作员角色过滤
  const authorizedEdges = outgoingEdges.filter(
    (edge) => edge.who.includes("any") || (myRole && edge.who.includes(myRole))
  );

  // 4. 将边映射为具体交互按钮
  return authorizedEdges.map((edge) => {
    const targetStatus = task.workflow.statuses.find((s) => s.value === edge.to);
    const label = edge.actionLabel ?? `转为: ${targetStatus?.label ?? edge.to}`;

    if (edge.via === "direct") {
      // 直转边：直接触发 taskTransit
      return {
        id: `transit_${edge.from}_${edge.to}`,
        label,
        tone: edge.actionTone ?? "default",
        onClick: () => executeDirectTransit(edge.to, edge.confirmMessage),
      };
    } else {
      // 审批边：调起发起审批 Dialog，指派答复人，发起 actionCreate
      return {
        id: `action_${edge.from}_${edge.to}`,
        label,
        tone: edge.actionTone ?? "outline",
        onClick: () => openActionDialog({ toStatus: edge.to, targetLabel: targetStatus?.label }),
      };
    }
  });
}
```

### 3.3 插件领域特有动作扩展点（Plugin Custom Actions）

插件可能有纯状态流转表达不了的高级业务（如：安全检查插件希望提供“一键全部合格”、“调取历史违规档案”）。  
插件在协议中声明 `customActions`，内核无缝并入顶栏按钮组：

```ts
export type PluginActionContext<TDef, TSub> = {
  taskId: string;
  taskStatus: string;
  myRole: string | null;
  definition: TDef;
  submission?: TSub | null;
  trpc: TRPCClient;
};

export type PluginActionDefinition<TDef, TSub> = {
  id: string;
  label: string;
  icon?: LucideIcon;
  tone?: "default" | "danger" | "outline" | "ghost";
  /** 何时可见：基于当前状态和角色计算 */
  visible: (ctx: PluginActionContext<TDef, TSub>) => boolean;
  /** 点击执行 */
  execute: (ctx: PluginActionContext<TDef, TSub>) => void | Promise<void>;
};
```

## 4. 插件完整协议契约定义 (`src/lib/task-plugins/types.ts`)

```ts
import type { ComponentType } from "react";
import type { z } from "zod";

export type TaskPluginMode = "edit_definition" | "inspect_answer" | "view_report";

export interface TaskPluginProps<TDef, TSub> {
  mode: TaskPluginMode;
  definition: TDef;
  submission?: TSub | null;
  onDefinitionChange?: (next: TDef) => void;
  onSubmissionChange?: (next: TSub) => void;
  disabled?: boolean;
}

export interface TaskPlugin<TDef = any, TSub = any> {
  /** 插件唯一代号，如 "safety-inspection" */
  id: string;
  /** 插件名称，如 "企业现场安全检查" */
  name: string;
  /** 业务描述 */
  description?: string;

  /** 题面定义数据校验器 */
  definitionSchema: z.ZodType<TDef>;
  /** 现场作答数据校验器 */
  submissionSchema: z.ZodType<TSub>;

  /** 默认空白题面 */
  initDefinition: (config?: unknown) => TDef;
  /** 默认空白作答 */
  initSubmission: (def: TDef) => TSub;

  /** 插件内聚贡献的一组默认流程模板 */
  workflows: ContributedWorkflow[];

  /** 插件自定义领域动作插槽 */
  customActions?: PluginActionDefinition<TDef, TSub>[];

  /** 列表卡片摘要提取器 */
  renderDigest?: (def: TDef, sub?: TSub | null) => string;

  /** 一体化三态呈现组件 */
  Component: ComponentType<TaskPluginProps<TDef, TSub>>;
}
```

## 5. 数据载荷与持久化设计

### 5.1 任务本体存储 (`tc_task.payload`)

任务存储依然由内核统一托管，题面与作答天然分离：

```json
{
  "pluginId": "safety-inspection",
  "version": 1,
  "definition": {
    "enterpriseName": "常州市顺安化工制造有限公司",
    "industry": "危化生产",
    "items": [
      { "id": "chk-1", "title": "灭火器压力指针在绿区", "category": "消防" },
      { "id": "chk-2", "title": "防爆配电箱接地良好", "category": "电气" }
    ]
  },
  "submission": {
    "answers": {
      "chk-1": { "result": "Y" },
      "chk-2": { "result": "N", "issue": "密封圈断裂老化", "photos": ["sys_file_photo1"] }
    },
    "completedAt": "2026-10-20T10:15:30Z",
    "inspector": { "id": "u_9921", "name": "李安监" }
  }
}
```

### 5.2 状态流转持久化与流水记录 (`tc_log`)
每次触发流转按钮推进状态时，内核在单个事务中原子完成：
1. 更新 `tc_task.status` 为目标状态；
2. 如果存在当前草稿提交，原子更新 `tc_task.payload.submission`；
3. 向不可变活动日志表 `tc_log` 插入一条记录：
   - `event: "task.transit"`
   - `from_status: oldStatus`
   - `to_status: nextStatus`
   - `actor_id: me.id`
   - `actor_name: me.name`

## 6. 全链路实战演练（以现场安全检查为例）

```
[1. 插件声明阶段]
插件 safety-inspection 导出:
- 题面定义: { enterpriseName, items: [...] }
- 作答定义: { answers: { [id]: { result, issue, photos } } }
- 贡献流程模板:
  状态链: draft -> inspecting -> pending_rectify -> closed
  边定义:
    - inspecting -> pending_rectify (who: ["executor"], actionLabel: "判定不合格，移交整改", tone: "danger")
    - inspecting -> closed (who: ["executor"], actionLabel: "合格归档", tone: "default")
- 插件特有动作:
  - [一键全选合格] (仅在 inspecting 态对 executor 可见)

[2. 任务创建阶段]
用户选择【企业现场安全检查】插件/流程 -> 加载模式 mode="edit_definition" -> 保存生成任务，初始态 = draft。

[3. 现场检查阶段 (Status = inspecting)]
- 插件主体模式: 自动推导为 mode="inspect_answer"，渲染打勾大按钮与相机拍照上传控件。
- 头部按钮栏: 内核动作引擎检索出边，自动渲染两个流转按钮:
  1. 绿色主按钮: [合格归档]
  2. 红色告警按钮: [判定不合格，移交整改]
  3. 插件自定义按钮: [一键全选合格]
- 现场人员打勾完毕，点击红色 [判定不合格，移交整改] -> 内核弹出前置确认 -> 确认后任务原子推进至 pending_rectify。

[4. 报告打印阶段 (Status = closed 或 pending_rectify)]
- 任何人进入任务，插件模式自动推导为 mode="view_report"。
- 页面渲染为 A4 排版格式，隐患自动标红，现场照片网格排列。
- 内核通用操作区提供 [打印报告] 按钮，一行调用 window.print() 输出标准现场检查文书。
```
