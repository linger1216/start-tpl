# 前端结构与组件约定(迁移自参考项目 std-address)

> 本文是**结构真源**:目录怎么分、一个业务域拆成哪些文件、组件接口怎么定、状态放哪、数据怎么流。
> 视觉规范(字体 / 字号 / 颜色 token / 间距圆角)见 `DESIGN.md` 与 `AGENTS.md`,本文不重复。
> 迁移来源:参考项目 `std-address` 的《组件封装与目录约定》+ `community` 样板模块。
> **维护约定:只写路径 + 符号名,不写行号。**

---

## 0. 三条硬规则

| # | 规则 | 违反后果 |
| --- | --- | --- |
| 1 | **依赖单向**:`routes → components/modules/<域> → components/{layout,ui,modules/shared} + lib + mocks` | 反向引用(`lib` import 组件)立刻制造循环,抽不动也测不了 |
| 2 | **一个业务域 = 一个目录**,文件名一律 `<域>-<角色>.<ext>` | 改一个功能 = 一次目录级 grep,而不是全仓搜索 |
| 3 | **不做通用增删改查封装**:没有公共 CRUD 组件 / 没有 `fields` 声明式驱动 | 每个域自己实现 table / form / detail,风格靠约定对齐,不靠一个万能组件 |

> 第 3 条是**本项目与参考项目的唯一硬性差异**。参考项目把重复写法抽成了 `lib/crud/*`(页面级 CRUD 封装),
> 本项目明确要求不抽公共增删改查组件,因此只保留"低阶复用件"(见 §3),重复写在各自域内。

```text

│  │  ├─ index.tsx               工作台
│  │  ├─ archive/…               数据档案
│  │  ├─ data/…                  数据底座
│  │  ├─ governance/…            数据治理

│  │  ├─ settings/…              系统设置
│  │  └─ reports/…               报表设计
│  └─ api.trpc.$.tsx             (本项目保留的 tRPC 示例入口)
│
├─ components/
│  ├─ ui/                        无业务语义的叶子原语(base-ui / shadcn 风格 + cva)

│        └─ __tests__/           域内测试(可选,只测纯逻辑)
│

│  └─ format.ts / utils.ts / constants.ts / …

└─ mocks/                        模拟数据(**契约中枢**,见 §2)
```

**别名统一 `#/*`**(映射 `./src/*`);`@/*` 已废弃。

## 2. 层映射:参考项目 → 本项目

参考项目前后端一体(tRPC + drizzle),本项目只有前端 mock,因此三层做等价替换:

| 参考项目 | 本项目 | 说明 |
| --- | --- | --- |
| `db/schema.ts`(字段名真源) | `src/mocks/<域>.ts` 的行类型与种子 | 模拟数据的字段名就是契约 |
| `lib/validators/<域>.ts`(契约中枢) | `src/mocks/<域>.ts` 的导出 | 行类型 / 枚举 / 导入导出列 / 统计口径都在这一个文件 |
| `server/api/routers/<域>.ts` | `createMockTable(seed)` 的内存 store | `insert / update / remove / replaceAll` 即写接口 |
| `RouterOutputs`(前端类型真源) | `src/lib/mock-table.ts` 的 `MockRow` + 各 mock 导出的 `XxxRow` | `<域>-table.tsx` 里 `export type XxxRow = …` 从 mock 推导 |
| `useCrudMutations` / `useCrudExcel` / `filter-store` | **不存在**(第 3 条硬规则) | 各域自己写写操作、导入导出与筛选状态 |
| `components/modules/<域>/` | 同 | `<域>` = mock 数据模块名 |

**判据(什么时候下沉到 `shared/`)**:第二个域要用 → 立刻提到 `modules/shared/` 或 `ui/`。
但**只允许下沉"无业务语义"或"领域无关形状"的件**;带某个域概念的表格 / 表单 / 详情**永不跨域复用**(参考项目只允许跨域复用 detail 弹窗,本项目进一步收紧:需要同构就各自写)。

## 3. 四个组件目录的分工

### 3.1 `components/ui/` —— 无业务语义的叶子原语

- 一个文件一个主组件,文件名 = 组件名 kebab-case(`confirm-dialog.tsx` → `ConfirmDialog`)。
- **一律具名导出**,不用 `export default`;变体用 `cva` + `VariantProps`,不要布尔堆叠。
- 组合型原语(内部有交互态但无业务语义)也放这里:`search-select`、`tag-input`、`badge-list`、`date-range-picker`。
- 弱业务原语(只依赖全局常量)可放这里:`status-badge`、`detail-row`、`json-cell`。
- **不要在这个目录里"顺手修 lint"**:`biome.json` 对它有 scoped override(见 `AGENTS.md`)。

### 3.2 `components/layout/` —— 应用外壳

`page-header` / `empty-state` / `stub-page` / `sidebar*` / `topbar` / `nav-config`(静态兜底 + 权限点派生 + 种子) / `nav-menu`(菜单表 → 导航树) / `module-overview`。

**每个页面第一屏都应是 `PageHeader`**,不要手写 `<h1>`;占位页用 `StubPage` 系,不留空文件。

### 3.3 `components/modules/shared/` —— 跨域但带业务语义

现有成员:`stat-cards` + `metrics`(指标口径)、`pagination-control`、`excel-import`、`tag-badges`、`mini-chart`(Bar/RankBars/Donut/Line/Timeline)、`catalog-banner`、`archive-profile`、`governance-rule-page`、`permission-tree`、`icon-picker` / `icons-list`。

接口要刻意做成**领域无关的形状**:

```tsx
// stat-cards.tsx:只吃一个 items 数组,数据由各域 *-stats.tsx 组装
export type StatItem = { key: string; label: string; value: number | string; description?: string; Icon: LucideIcon; tone: string };
```

> 注意:`archive-profile.tsx` 与 `governance-rule-page.tsx` 是**迁移前遗留的"域专属形状通用件"**。
> 按 §0 第 3 条,它们要在对应域拆分时**下沉进域目录**(`archive/`、`governance/`),不再留在 `shared/`。

### 3.4 `components/modules/<域>/` —— 业务域

- 目录名 = mock 数据模块名(`src/mocks/data/works.ts` ↔ `components/modules/data-works/`)。
- 文件前缀 = 目录名,后缀 = 角色(§4)。
- **跨域复用**:只允许复用"无业务语义的件"与"领域无关形状的展示件";表格 / 表单 / store 一律不跨域。
- 页面私有子组件(只有本页用的 `Field` 行、`SortIcon` 之类)**就近定义在同文件底部**,不单独开文件。
- 一个域有多个页面时:`<域>-<页面>-page.tsx`(参考项目 `complaints` 域的 `complaints-page.tsx` + `person-house-page.tsx` 就是这个形态)。

## 4. 域内文件角色(后缀即契约)

| 后缀 | 角色 | 约定 |
| --- | --- | --- |
| `<域>-page.tsx` | 页面编排壳 | 唯一的数据订阅与写操作入口;组合 Header / Stats / 工具栏 / Table / Pagination / Dialogs。`export function XxxPage()` |
| `<域>-table.tsx` | 列定义 + 表格 | `export type XxxRow` + `createXxxColumns(callbacks)`(列工厂)+ `XxxTable({ table, emptyText })` |
| `<域>-form.tsx` | 新建 / 编辑弹窗 | 受控 Dialog;`open` / `onOpenChange` / `initial` / `onSubmit` / `isPending` 五件套 |
| `<域>-form-mappers.ts` | **纯**映射 + 校验 | 无 React 依赖;导出 `emptyForm` / `toForm(initial)` / `toSubmit(values)` / `validate(values)`;表单逻辑唯一可单测的落点 |
| `<域>-detail.tsx` | 只读详情 | 吃 `detail` 数据 + `open` / `onOpenChange`;行内容用 `DetailRow`、多值用 `TagBadges` |
| `<域>-stats.tsx` | 顶部指标卡 | 吃"已算好的行数据 / 计数",组装 `StatItem[]` 交给 `StatCards`;不要在组件里直接读 store |
| `<域>-<域内名>.ts(x)` | 域内纯 helper / 子编辑件 | 如 `<域>-columns.ts`(列宽 / 枚举映射)、`<域>-split-screen.tsx`(域内专属交互件) |
| `stores/<域>-store.ts` | 域内 zustand store | 仅当页面 UI 态需要被多个子组件共享时才建;只有一个编排壳用 `useState` 即可 |
| `__tests__/*.test.ts` | 域内测试 | 只测纯逻辑(mappers / 概算函数),不渲染组件 |

**`.ts` 与 `.tsx` 的边界是硬的**:`.ts` 不含 JSX、不 import React。

### 4.1 三条落地细节(以 `data-works` 为样板校准过)

1. **行类型只有一个家**:`<域>-table.tsx` 里 `export type XxxRow = …`(本项目从契约中枢 `#/mocks/<域>.ts` re-export 而来)。
   UI 文件(`-page` / `-form` / `-detail` / `-stats`)一律 `import type { XxxRow } from "./<域>-table"`;
   **纯映射层**(`-form-mappers.ts`)只依赖 `#/mocks/*` 的类型,不反向依赖组件文件。
2. **"数据契约"下沉,不留在页面**:Excel 列(表头文案 / 必填 / 列宽)、标签命中计数这类**描述数据本身**的东西放契约中枢
   (如 `WORK_EXCEL_COLUMNS` / `workTagCount`),页面只负责渲染与调度 —— 改字段时只改一处。
   判据:一句话能用"这份数据长什么样"描述完 → 进契约中枢;必须提到"按钮/颜色/布局" → 留在域内 UI。
3. **列表页不额外起行**:选中态控件(已选 N 条 / 批量删除)并入工具栏同一行并替换右侧操作组,
   行高与搜索框一致(`h-8`),选中前后表格位置不变;搜索框用 `flex-1` 吃掉剩余宽度,右侧组 `ml-auto min-w-72` 固定宽度。

## 5. 组件封装约定

### 5.1 导出与命名

- 一律具名导出;不给"将来可能有用"的符号加 export。
- 文件 kebab-case;组件 / 类型 PascalCase;函数 camelCase;常量 `UPPER_SNAKE_CASE`。
- 注释解释**为什么**,不解释**做什么**。

### 5.2 组件边界:谁读数据

- **数据订阅只出现在 `<域>-page.tsx`**(或域内 hook)。`-table` / `-detail` / `-stats` / `-form` 只收数据 + 回调。
- 写操作(新增 / 编辑 / 删除 / 批量删除 / 导入)也集中在编排壳:子组件通过回调把"领域值"上抛。
- 组件不自己 `toast` 业务结果;统一在编排壳里提示(本项目数据是内存 mock,无网络错误,故提示文案极简)。

### 5.3 props 形状:受控 + 回调,状态留在编排层

弹窗固定五件套:

```tsx
<XxxFormDialog
  open={form !== null}
  onOpenChange={(v) => { if (!v) setForm(null); }}
  initial={form?.row ?? null}   // null = 新建
  onSubmit={(values) => { … }}  // 只回传领域值,不回传事件
  isPending={false}
/>
```

表格固定四件套:

```tsx
<XxxTable table={table} emptyText="暂无数据" />
```

要点:受控开合;回调回传领域值;可选参数给默认值;泛型组件显式传参(`SearchSelect<T extends string>`)。

### 5.4 列定义用工厂函数

```ts
export type WorkRowCallbacks = {
	onView?: (row: WorkRow) => void;
	onEdit?: (row: WorkRow) => void;
	onDelete?: (row: WorkRow) => void;
};

export function createWorkColumns(callbacks: WorkRowCallbacks) {
	return columnHelper.columns([ /* 数据列 + actions 列 */ ]);
}
```

- 列工厂让"列"脱离渲染独立存在,回调靠闭包注入,不把 `setState` 穿透进表格。
- 列宽用 `size`,对齐 / 额外 class 挂 `columnDef.meta.className`(`lib/table.ts` 已扩展 `ColumnMeta`)。
- 表格特性统一加在 `src/lib/table.ts` 的唯一 `createTableHook` 里,各域不自定义。
- 需要"选中 + 批量删除"的页面,select 列由**该域的**表格文件自己写(不共用)。

### 5.5 筛选与分页

- 简单页:编排壳内 `useState`(搜索词 / 页码 / 每页条数 / 排序 / 选中)。
- 需要跨子组件共享时:域内 `stores/<域>-store.ts`(`zustand`),不放服务端数据。
- 改筛选 / 排序 / 每页条数**一律回到第一页**。
- **筛选维度要对着"页面上真实存在的那张表"**:若某个筛选组的唯一用途是过滤一张已经移进弹窗的子表(`/settings/tags` 就是这种情况 —— 明细表改为"点维度弹出"后,「所属维度」筛选组随之整段删除),就不要保留这条筛选条,否则会变成对着一张不存在的表筛选。判定标准:删掉那张表之后,这个筛选组还有没有意义。

## 6. 数据流

```text
src/mocks/<域>.ts(行类型 + 种子 + 枚举,契约中枢)
   └─ createMockTable(seed) 的内存 store(lib/mock-table.ts)
        └─ components/modules/<域>/<域>-page.tsx   订阅 store(rows)+ 写操作(insert/update/remove/replaceAll)
             ├─ <域>-table.tsx    createXxxColumns({ onView, onEdit, onDelete })
             ├─ <域>-stats.tsx    吃行数据算指标
             ├─ <域>-form.tsx     → <域>-form-mappers.ts(toForm / toSubmit / validate)
             └─ <域>-detail.tsx   吃行数据
```

规则:

1. 行数据即详情 / 编辑的数据源(一条记录带全部展示字段),不再单独"按 id 查询"。
2. 导出与列表**共用同一套筛选**:导出走"已过滤行",不分页。
3. 导入先经 `<域>-form-mappers.ts` 的行映射(文本 → 领域值),再 `insert` / `replaceAll`。
4. 展示格式化走 `lib/format.ts` 与 `lib/multi-value.ts`,不在组件里手写拆分逻辑。

## 7. 路由约定

`src/routes/` 全是**薄壳**,一个页面一个文件,通常 5~7 行:

```tsx
import { createFileRoute } from "@tanstack/react-router";

import { DataWorksPage } from "#/components/modules/data-works/data-works-page";

export const Route = createFileRoute("/(main)/data/works")({
	component: DataWorksPage,
});
```

- 带参数的详情页:**路由读参数,页面收 `id` prop**(页面不 import 路由文件,避免循环依赖):

```tsx
export const Route = createFileRoute("/(main)/archive/works/$id")({
	component: ArchiveWorkDetailRoute,
});

function ArchiveWorkDetailRoute() {
	const { id } = Route.useParams();
	return <ArchiveWorksDetailPage id={id} />;
}
```

- 未开发的页面直接 `component: StubPage`,不留空文件。
- `routeTree.gen.ts` 是生成物,改完路由跑 `pnpm generate-routes`。

## 时间处理约定(强制)

**所有时间格式化/解析都走 `src/lib/time.ts`,不要在业务代码里自己写。**

- 给人看:`formatLocalDateTime`(`YYYY-MM-DD HH:mm:ss`)/ `formatLocalMinute`(列表列窄时用);
- 给机器传:接口参数用 `toISOString()`(ISO-8601);SQL/游标用 `formatLocalSql`(与 MySQL `datetime` 同语义);
- **禁止**把 `toISOString()` 的结果当"给人看的时间" —— 它是 UTC,UTC+8 下会差 8 小时。
  这个坑真实出现过两次:一次让增量窗口把整批数据滤掉(同步一条都拉不到),一次让界面时间提前 8 小时。

## 数据源接入配置只有一处(强制)

**接入配置(连接、路径/表、翻页方式及其参数、增量及其参数、请求参数)只在「新增/编辑数据源」表单里配一次。**

- **同步入口不做二次配置**:同步面板只做两件事 —— 触发同步、看结果(状态徽章 + 上次结果 + 立即同步 + 去改配置)。
- 为什么:配置是"从对方那头取数"的前提,分布在两处必然出现"改了一处、另一处还是旧的";而且新增时配不全,等于让人建完再回来补。
- 要改配置 → 同步面板的「去改配置」回到那张表单,不在同步流程里再开一个配置界面。
- **验收口径**:新建流程必须能一次把全部配置做完;同步面板里**不允许出现任何配置输入框**。

## 改完必须自测,通过才算完成(强制)

配置类改动(**接入配置、规则字段、表单校验**这类"改错了要等运行时才发现"的)必须:

1. 改完先跑 `pnpm test:sync` 与 `pnpm test:ui`;
2. 再加/改用例覆盖这次改动(尤其"不该出现的东西没出现"这类反向断言);
3. **用例全绿才算完成** —— 不许以"看起来没问题"作为完成标准。

## 显示名对外,业务键只在配置界面(强制)

页面上一切"这是什么字段"都用**显示名**(`data_entity_field.label`,如「统一信用代码」),**不把业务键摆到普通操作面前**
(`social_credit_code` 这种只该出现在配置/接口口径里)。同一份键与显示名的对照处处适用:

- **列表**:列头用显示名;**判重键列**也用它的显示名(`统一信用代码(判重键)`)—— 判重键的值本身来自某个属性,那个属性的名字就是它的名字;
- **搜索提示 / 导出列名**:同上(导入时显示名与「判重键」都认,导出回填不会断);
- **详情页**:大标题取档案名(按类别的 `nameField`),副标题写「显示名 + 真实值」,基本信息网格的每行 label 都是显示名;
- **编辑弹窗**:已登记属性**只显示显示名**(不给业务键输入框);只有"新增一个从来没人用过的属性"才需要填键 ——
  那时它还没有显示名,键由人来起;键名只放在 hover 的 `title` 里备查;
- **实现**:显示名只有一个来源(`data_entity_field`),前端不要再写 `KEY_LABELS` 之类的第二份对照表。

## 档案详情页:版式与演示档案共用一份(强制)

「演示档案」(`/archive/*`)与「数据档案」(`/data-archive/*`)的**详情页必须是同一套版式**:
`ArchiveProfile`(页头 + 档案主体摘要 + 按关联业务划分的 tab)+ `ArchiveRelationTable`(tab 内的只读关联表)。
关联业务的**列声明**也只写一份(`modules/archive/archive-enterprise-relations.ts`),两个消费方共用 ——
抄两份必然有一天两张表长得不一样,而每加一个关联业务就要改两处。

真实档案的详情页三类数据要分得清,并且**在页面上写明白**:

| 数据 | 来源 | 页面上怎么标 |
| --- | --- | --- |
| 基本信息 / 判重键 / 来源记录 / 关联关系 | `data_entity` / `data_raw` / `data_rel` | 直接展示(**真实数据**徽章) |
| 走访 / 安全检查 / 处罚 / 体检等还没接入的关联业务 | 演示档案的同一份 mock | **必须**带「演示数据 · 还没有接入真实数据源」提示条,不冒充真实档案;接入后只换数据源,列不用动 |

## 表格列可见性(强制)

列由数据决定、列数会变多的表格(档案台账、数据明细)**一律挂 `ColumnVisibilityMenu`**,不要各页各写一套。

- 可见性存**系统设置**,不存 localStorage:键是 `sys_config` 里的 `ui.columns.<tableKey>`,值是**可见列的键数组**的 JSON。
  - 档案台账:`ui.columns.archive.<category>`;数据明细:`ui.columns.raw.<sourceId>`。
  - 为什么存服务端:这是"系统设置"级偏好 —— 换机器/换浏览器都该一致,而且要在「系统设置 ▸ 参数管理」里能直接改这串 JSON。
- **不写这个键 = 全部可见**(与"所有列都显示"的默认一致);「恢复默认」= 写回全量。
- 存的是"**可见**列的清单",所以**清单之外的新列默认隐藏**:以后给这个类别登记了新属性 / 给数据源加了映射字段,新列不会自己冒出来 —— 点一次「全选」即可(这是"可见清单"语义的已知代价,换来的是"默认全显示、只减不增"的可预期行为)。
- 键必须**稳定**:用业务字段名 / 属性键,不要用列下标 —— 否则改字段顺序会让偏好错位到别的列上。
- 台账的实现只做两件事:`fields.filter((field) => cols.isVisible(field.key))` 之后再去画列;`ColumnVisibilityMenu` 的 `items` 传**全量**列(被隐藏的也要在面板里出现,否则再也勾不回来)。
