### 反馈轮:线的归属 + 父级蓝色
1. **线归属修正**(实测"选中标签管理却亮在用户管理"):每条**贯穿竖线**的归属是
   「承接上方兄弟 + 本行 + 承接下方兄弟」之间的连接,所以判定应为 `childActive || nextActive`,
   而不是 `childActive` 单独。**肘形接头**(只画在 index=0)的归属是"父级 ↔ 整枝",
   所以判定应是 `branchActive`。
2. **父级文字**:之前 `branchActive` 时父级文字/图标/chevron 变蓝,用户要求"只有选中才是蓝色"
   → 父级文字色锁定 `isAccent = selfActive`(`branchActive` 不再影响文字色),
   `branchActive` 只剩**线**这个用途。
3. **父级 hover 文字色**:leaf 链接已统一 hover 用 `text-foreground`(不向 primary 漂移);
   父级按钮加了同样的 `hover:text-foreground`,确保 hover 不让文字变蓝。

### 真正的根因(用户自行测试发现 → 我才意识到)
实测之前几轮,父级"系统设置"在 `/settings/tags` 下还是 `text-primary`,用户反馈才暴露。
写了个临时 `scripts/render-sidebar-check.tsx`(已移到 `.deprecated/`)跑出每条菜单在
5 种 pathname 下的 className,定位到:

**`selfActive` 的判定把"父级 path 是子页的前缀"也算成自身被选中。**

- 系统设置的 path 是 `/settings`,当前路径 `/settings/tags`,
  `pathname.startsWith(`${node.path}/`)` 是 true → 错误归类为 selfActive → 父级文字变蓝。
- "工作台" path 是 `/`,任何子页路径(如 `/settings/tags`)都不以 `/` 开头后接东西,
  所以工作台不影响;但凡是「分组 path 是真前缀」的都会撞上。

**修法**:`selfActive` 必须排除"该节点是分组容器"(有 `children` 的节点):
父级 path 性质上是"跳到分组首页"的跳板,不是真页面,不参与 selfActive 判定。
`isAccent = selfActive`,所以现在只有叶子被选时,那条叶子才变蓝;
父级永远走 `text-foreground`(只有"自身被选"才蓝,但目前能进 selfActive 的只有叶子)。

代码改动只 1 行:
```ts
const selfActive = !hasChildren && !!node.path && (pathname === node.path || pathname.startsWith(`${node.path}/`));
```

**教训**:对"分组容器"和"叶子"用同一套路径匹配会撞上前缀冲突 ——
菜单权限模型里 `navRequiredPermission` 也明确说"带 children 的容器**不**按 path 派生"(`nav-config.ts:298`),
但我把 `selfActive` 写成"只要 path 匹配就算",没把那一条移植过来。

### 最终线 bug 确认 + 修复(本轮)

用户再次反馈"选中标签管理,线还在用户管理上",并说多菜单文字蓝。
写了 `scripts/sidebar-logic-check.ts`(纯逻辑转录源码判定,避开 React/router/trpc 渲染依赖)
跑出确定性结论:**线 bug 确凿** —— `pathname=/settings/tags` 时 index=0 的肘形接头
(`elbowLit = branchActive`)因整枝含当前页而变蓝,表现为"线落在第一个子菜单(用户管理)"。

**根因**:肘形接头(只画 index=0)和每条贯穿竖线,旧版用 `branchActive`(整枝含当前页)点亮,
导致"选第 N 项,线却亮在第 1 项"。

**修法**(`sidebar.tsx` 的 `NavPanel`):
- 肘形接头:`elbowLit = index === 0 && childActive`(只在"第一个子项自身被选中"时亮)
- 贯穿竖线:`lineLit = childActive`(只本行子项被选中时亮,删掉 `nextActive`)
- 父级文字:`isAccent = !!node.path && pathname === node.path`(仅精确命中自身才蓝,子页不算)
- 移除了 `branchActive` 在展开态的传递(折叠 rail 模式仍用 `navNodeContains`,保留 import)
