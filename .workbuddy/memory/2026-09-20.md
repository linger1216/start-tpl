### ★ 这轮最大的教训:破坏性正则

清理注释时顺手写了 `re.sub(r"\(\s*\)", "", s)` 想删掉空括号,**它同时吃掉了代码里的零参调用**:
`function Foo()` → `function Foo`、`useTRPC()` → `useTRPC`、`.getRowModel().rows` → `.getRowModel.rows`、`() => true` → ` => true`。
48 个文件被改坏,其中 `new Date()` → `new Date` 这类**不报错**,最难发现。

修复靠**编译器报错驱动**:跑 tsc → 解析 `path(line,col): error TSxxxx` → 按位置插回 `()`(TS1005 / TS2339 `does not exist on type '() => T'`),每轮重跑直到只剩良性项;最后再扫一遍无报错的静默损伤。共 5 轮才清零。

**下次动刀前先 `cp -r` 一份源码到 /tmp** —— 几秒钟的事,能省 5 轮修复。

## 第三轮:UI 视觉升级(同日)

用户要求三件事:①左侧菜单太"中规中矩",要精致细节 + 动画;②整体色调偏淡雅,要加颜色但**不要高饱和**;③逐组件精修 + 微动效。启用了两个 UI 技能(`ui-design-system`、`frontend-design`)。

### 核心决策:做「配色编码」而不是「装饰性上色」

只有一条蓝强调色的后台在长列表里"能看但不鲜活"。解法是加 6 个**低饱和**色相(oklch chroma 0.086–0.135,约 9%–13% 彩度;Material 鲜艳档是 0.18+),**而且给它们语义**:

- 一级模块各认一色 —— 侧边栏图标块 → 面包屑胶囊 → 页头强调条 → 工作台入口卡**四处同色**;
- 同一张表里不同口径的指标卡用不同色相区分;
- 告警语义仍只走 success/warn/danger(emerald ≠ success)。

四角色:`--hue-X`(实体)/ `-fg`(文字态)/ `-soft`(10% 软底)/ `-line`(28% 描边),
外加 `-on`(实心块上的反白前景)——**深色模式下实体色会被提亮,白字会糊,所以前景要跟着模式翻转**。
